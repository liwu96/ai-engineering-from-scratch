# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Repository Overview

This is **AI Engineering from Scratch** — a comprehensive 435-lesson, 20-phase curriculum teaching AI/ML from first principles. Each lesson follows a six-part structure: Problem → Concept → Build It (from scratch) → Use It (frameworks) → Ship It (reusable artifacts) → Exercises.

**Key Principle:** Code is built from scratch first, then shown with frameworks. No comments in code — explanations live in docs.

## Directory Structure

```
phases/                    # 20 phases, each containing lessons
  NN-phase-name/
    NN-lesson-name/        # Individual lesson folder
      ├── code/            # Runnable implementations (Python, TypeScript, Rust, Julia)
      ├── docs/
      │   └── en.md        # Lesson documentation (required)
      ├── notebook/        # Jupyter notebooks (optional)
      ├── outputs/         # Prompts, skills, agents produced by lesson
      └── quiz.json        # Phase quiz questions

site/                      # Static website (aiengineeringfromscratch.com)
  ├── build.js             # Parses README.md, ROADMAP.md → data.js
  └── *.html, *.css, *.js  # Site files

scripts/                   # Development utilities
outputs/                   # Curriculum-wide outputs index
  ├── prompts/
  ├── skills/
  ├── agents/
  └── mcp-servers/

glossary/
  └── terms.md             # AI/ML terms with "what people say vs what it means"
```

## Common Commands

### Validate and Test

```bash
# Syntax-check all lesson Python code (does not execute)
python scripts/lesson_run.py

# Check specific phase
python scripts/lesson_run.py --phase 14

# Execute lessons (requires dependencies, 10s timeout)
python scripts/lesson_run.py --execute

# Audit lesson structure and invariants
python scripts/audit_lessons.py

# Strict audit (exit 1 on issues)
python scripts/audit_lessons.py --strict
```

### Build and Deploy

```bash
# Build site data (must run after editing README.md or ROADMAP.md)
node site/build.js

# Build machine-readable catalog
python scripts/build_catalog.py

# Output to stdout without writing file
python scripts/build_catalog.py --stdout
```

### Install Skills/Prompts

```bash
# Install all curriculum skills to ~/.claude/skills/
python scripts/install_skills.py ~/.claude/skills/ --type skill

# Install prompts only
python scripts/install_skills.py ~/.claude/skills/ --type prompt

# Install by phase
python scripts/install_skills.py ~/.claude/skills/ --phase 14

# Dry run to preview
python scripts/install_skills.py ~/.claude/skills/ --dry-run
```

### Create New Lessons

```bash
# Scaffold new lesson (creates folder structure)
scripts/scaffold-lesson.sh <phase-dir> <lesson-slug> [title]

# Examples:
scripts/scaffold-lesson.sh 05-nlp-foundations-to-advanced 03-tokenizers
scripts/scaffold-lesson.sh 05-nlp-foundations-to-advanced 03-tokenizers "Tokenizers from Scratch"
```

## Code Style and Conventions

- **No comments in code.** Code must be self-explanatory; explanations belong in `docs/en.md`
- **Code must run.** Every file should execute without errors with listed dependencies
- **Best language for the job.** Don't force Python where TypeScript or Rust is better
- **Build from scratch first.** Always implement from first principles before showing framework version
- **Keep it practical.** Theory serves practice
- **Direct prose in docs.** Cut filler, match the manual's tone

## Key Files for Editing

- `ROADMAP.md` — Phase/lesson status tracker (feeds website, keep status glyphs: ✅ 🚧 ⬚)
- `README.md` — Main documentation (phase headers must keep `X lessons` format for parser)
- `glossary/terms.md` — Term definitions with "what people say vs what it actually means"
- `catalog.json` — Machine-readable curriculum catalog (auto-generated)
- `site/data.js` — Website data (auto-generated by `node site/build.js`)

## Lesson Structure (docs/en.md)

```markdown
# Lesson Title

> One-line motto — the core idea in one sentence.

## The Problem
Why does this matter? What can't you do without this?

## The Concept
Explain with diagrams, visuals, intuition. No code yet.

## Build It
Step-by-step implementation from scratch.

## Use It
Framework/library version of the same thing.

## Ship It
The prompt, skill, agent, or MCP server this lesson produces.

## Exercises
1. Easy — reinforce the core concept
2. Medium — apply to different problem
3. Hard — extend or combine with prior lessons
```

## Contributing Workflow

1. Edit files (lessons, ROADMAP, README)
2. Run `node site/build.js` if you touched README.md or ROADMAP.md
3. Run `python scripts/lesson_run.py` to verify code syntax
4. Run `python scripts/audit_lessons.py --strict` for structure validation
5. Atomic commits: one lesson per PR for clean review
