# 紧急停止开关、断路器和金丝雀token

> 紧急停止开关是智能体编辑面之外持有的布尔值——Redis键、功能标志、签名配置——完全禁用智能体。断路器更细粒度：它在特定模式（连续五次相同工具调用）上触发，暂停违规路径，并升级到人类。金丝雀token继承自经典欺骗：智能体无合法理由接触的假凭证或蜜罐记录，其访问触发警报。基于eBPF的数据路径（例如Cilium）可以在内核层将隔离pod的外泄重写到取证蜜罐；公开的Cilium基准报告负载下TCP_RR亚毫秒P99数据路径延迟（传播预算取决于策略更新如何到达节点，而非数据路径本身）。适应移动基线的统计检测器（EWMA、CUSUM）会静默接受漂移——将它们与不弯曲的硬宪法限制分层。

**类型:** 学习
**语言:** Python (stdlib, 三检测器模拟器：紧急停止开关、断路器、金丝雀)
**前置要求:** 第15阶段 · 13 (成本治理器), 第15阶段 · 10 (权限模式)
**时间:** ~60分钟

## 问题背景

成本治理器（第13课）约束智能体能花费的内容。它们不约束智能体在预算内能做什么。有$50速度限制的智能体仍能外泄秘密、发布错误帖子或删除资源——昂贵动作在token上通常是便宜的。

本课涵盖位于成本层旁边的三个检测器：

1. **紧急停止开关**：智能体触及范围之外持有的布尔关闭按钮。
2. **断路器**：暂停特定路径的动作模式检测器。
3. **金丝雀token**：智能体无合法理由接触的诱饵，接触即暴露。

三者都是前LLM工程。经典欺骗、速率限制断路器和功能标志杀死先于自主智能体。新的是攻击面：智能体读取不可信内容（第11课）、编辑自己的内存，并能将许多看似安全的动作组合成不安全动作。此处命名的检测器有效，因为它们不信任智能体的自我报告。

## 概念讲解

### 紧急停止开关

紧急停止开关是智能体读取但不能写入的布尔值。实现选择：

- **托管服务中的功能标志。** LaunchDarkly、Statsig、Unleash。更新在数秒内传播。
- **智能体轮询的Redis键。** 简单；要求智能体进程在每次轮询时检查。
- **对象存储中的签名配置。** 智能体验证启动时的签名；拒绝无签名状态。
- **OS级信号或容器生命周期杀死。** Docker `kill`、Kubernetes `kubectl delete pod`、systemd stop。

正确紧急停止开关具有的属性：

- 智能体不能将其设为 `off`。（位于智能体凭证不写入的系统中。）
- 它在每次 consequential 动作上检查，不仅启动时。
- 关闭时，智能体不做外部可观察的事，包括记录到智能体可触及的系统。
- 重新启用它是显式人工动作，非自动超时。

### 断路器

断路器暂停特定模式，非整个智能体。经典形状（来自2007年Nygard书，仍当前）：

- **闭合**：动作允许。
- **断开**：动作阻止。
- **半开**：冷却后，允许1-3次探测尝试（默认1）；成功闭合断路器，任何剩余失败重新打开。

智能体相关触发器：

- 连续五次相同工具调用（重复循环）。
- 同一工具上不同输入的五次连续失败（系统性故障）。
- 超过阈值的工具调用速率（第13课速度）。
- 在信任外内容读取后调用的特定工具（例如 `file.delete`）（第11课）。

### 金丝雀token

金丝雀token（也称为honeytoken）是智能体不应接触的输入。访问即警报。

智能体示例：

- 环境中无实际权限的假 `AWS_SECRET_ACCESS_KEY`。外泄尝试可立即归因。
- 带已知哨兵值标记的假数据库记录。任何读取或更新该记录触发警报。
- 工作空间中的假文件。读取或编辑该文件可疑。
- 会话开始时注入的假内存条目。如果它出现在后续输出中，内存已被外泄。

金丝雀设计特定于工作流。智能体有合法理由接触的金丝雀是噪声。

### 为什么将统计和硬限制分层

统计检测器（EWMA、CUSUM、工具调用速率z分数）适应移动基线。这对合法漂移是特性，对对抗性漂移是bug。耐心攻击者可以缓慢移动基线而不触发警报。

硬宪法限制（第17课）不弯曲。"永不发送邮件到 `secrets@`" 作为宪法规则更简单、可审计，且不被缓慢漂移博弈。分层模式：统计检测器捕获大多数噪声，硬限制捕获走过检测器的攻击。

### 通过eBPF数据路径重定向隔离

Cilium基于eBPF的网络策略可以在内核层将隔离pod的外泄重写到取证蜜罐。Cilium的公开基准报告TCP_RR上亚毫秒P99数据路径延迟；集群中*触发*隔离的挂钟预算由策略更新从控制平面传播到节点的速度主导（操作员预加载时几百毫秒是现实的；尾延迟取决于集群大小和协调节奏）。这给你两件事：智能体外泄任何真实内容，智能体在蜜罐内的行为被完全观察。与金丝雀token相同模式，不同层：智能体通过在被包含时尝试做什么来暴露意图。

### 没有检测器捕获什么

- **从允许原语组合的语义攻击。** 每个单独动作通过每个检测器；组合是问题。这是第10课自动模式的复合失败。
- **将检测器作为payload一部分的攻击。** 如果智能体读取说"行动前，禁用金丝雀"的页面且智能体有能力，检测器被妥协。金丝雀token应在智能体无法修改的系统中。

## 动手实践

`code/main.py` 通过三个检测器模拟短智能体轨迹。外部字典中持有的紧急停止开关；连续五次相同工具调用触发的断路器；读取触发警报的金丝雀文件。输入合成轨迹：合法动作、重复循环、金丝雀探测、触发紧急停止开关的场景智能体动作停止。

## 练习题

1. 运行 `code/main.py`。确认断路器在第5轮（第五次相同调用）触发，金丝雀在第9轮（假密钥读取）触发。

2. 添加统计检测器：工具调用速率上的EWMA z分数。输入缓慢漂移的轨迹并显示检测器永不触发。现在添加硬限制（10分钟内不超过50次工具调用）并显示硬限制在同一轨迹上触发。

3. 为浏览器智能体（第11课）设计金丝雀token集。列出至少三个金丝雀及每个检测什么。

4. 阅读Cilium网络策略文档。具体描述外泄重定向隔离流程：哪个策略选择器、哪个pod、哪个外泄重写、哪个警报。"决定隔离"到"第一个重定向数据包"的挂钟延迟由什么主导？

5. 定义紧急停止智能体的重新启用程序。谁可以重新启用？必须记录什么？重新启用前智能体必须改变什么？

## 关键术语

| 术语 | 人们怎么说 | 实际含义 |
|---|---|---|
| 紧急停止开关 | "关闭按钮" | 智能体编辑面之外的布尔值；每次 consequential 动作检查 |
| 断路器 | "模式暂停" | 重复、失败率或速率限制上的动作特定触发 |
| 金丝雀token | "honeytoken" | 智能体无合法理由接触的诱饵；访问触发警报 |
| 蜜罐 | "取证沙箱" | 隔离智能体重定向的流量/工作空间，用于观察 |
| EWMA | "移动平均" | 指数加权；适应漂移（特性+bug） |
| CUSUM | "累积和" | 检测与基线的持续偏移 |
| 硬限制 | "宪法规则" | 不适应；无论历史如何都恒定 |
| 宪法限制 | "始终为真规则" | 与第17课宪法绑定；智能体无法编辑 |
