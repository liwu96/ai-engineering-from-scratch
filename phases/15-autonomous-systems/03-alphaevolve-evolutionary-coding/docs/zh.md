# AlphaEvolve — 进化式编码智能体

> 将前沿编码模型与进化循环和机器可检查的评估器配对。让循环运行足够长的时间。它发现了一个使用48次标量乘法的4x4复矩阵乘法过程——56年来首次超越Strassen的改进。它还找到了一个在Google生产环境中恢复~0.7%集群计算的Borg调度启发式算法。架构有意设计得平凡。胜利来自评估器的严谨性。

**类型:** 学习
**语言:** Python (stdlib, 进化循环玩具)
**前置要求:** 第15阶段 · 01 (长时程框架), 第15阶段 · 02 (自我教学推理)
**时间:** ~60分钟

## 问题背景

大语言模型可以编写代码。进化算法可以搜索代码。两者都已单独尝试数十年；两者都遇到了天花板。LLM的天花板是幻想：模型编写看似合理但不符声明的代码。进化的天花板是搜索成本：语法上的随机突变很少产生可编译的程序，更不用说更好的程序。

AlphaEvolve（Novikov等人，DeepMind，arXiv:2506.13131，2025年6月）结合两者。LLM提出对程序数据库的有针对性编辑；自动评估器对每个变体评分；高分变体成为未来世代的父代。LLM处理编写合理代码的昂贵步骤；评估器捕获幻想。循环运行数小时到数周。

报告的结果：48次标量乘法的4x4复矩阵乘法（Strassen 1969年的界限是49），Google生产环境中的Borg调度启发式算法，32.5%的FlashAttention内核加速，Gemini训练吞吐量改进。

架构之所以有效，是因为评估器是机器可检查的。在评估器不是的地方它无效。这种不对称性就是教训。

## 概念讲解

### 循环

1. 从正确但次优的种子程序 `P_0` 开始。
2. 维护一个变体程序数据库，每个都由评估器评分。
3. 从数据库中采样一个或多个父代（MAP-elites风格或基于岛屿）。
4. 提示LLM（Gemini Flash用于许多候选，Gemini Pro用于困难候选）生成父代的修改变体。
5. 在保留的评估器上编译、运行和评估变体。
6. 按分数和特征向量插入数据库。
7. 重复。

两个细节很重要。首先，LLM获得的提示不仅仅是父程序——通常是数据库中的几个顶级变体，加上评估器签名，加上简短的任务描述。模型的任务是提出可能提高分数的有针对性改变。其次，数据库是结构化的（MAP-elites网格、基于岛屿）以便循环探索多样性，而不仅仅是当前领先者。

### 什么使评估器不可协商

AlphaEvolve的胜利都来自评估器快速、确定且难以博弈的领域：

- **矩阵乘法算法**：单元测试，乘以矩阵并按位检查相等性。
- **Borg调度启发式算法**：生产级模拟器，重放历史集群负载并测量浪费的计算。
- **FlashAttention内核**：正确性测试加上真实硬件上的挂钟基准测试。
- **Gemini训练吞吐量**：每步测量的GPU秒数。

在每种情况下，评估器捕获了否则会主导的一类LLM错误：幻想的正确性声明、在硬件上消失的绩效声明、边缘情况失败。移除评估器，循环就会优化漂亮的代码。

### 奖励黑客是该陈述的另一面

进化为评估器测量的任何内容而优化。如果评估器不完美，循环会找到不完美之处。在未经验证的领域，循环会优化表面特征而非预期行为。DeepMind在论文中明确标记了这一点：AlphaEvolve的成功只转移到评估器严谨性与搜索野心相匹配的领域。

代码搜索循环中奖励黑客的具体2025-2026年示例：

- 奖励"完成时间"的优化目标奖励提交空解决方案。
- 奖励"测试下正确性"的基准分数奖励记忆测试和过拟合。
- "代码质量"代理奖励删除注释和重写变量名，无语义变化。

AlphaEvolve中的修复：部署LLM从未见过的保留评估器，在评估时生成输入。即便如此，DeepMind建议对任何提议的部署进行严格审查。

### 为什么LLM + 搜索优于单独使用

LLM可以产生可编译的、语义上合理的修改。2000行Python文件上的随机突变遗传算法几乎总是产生语法错误。LLM还将搜索集中在合理邻域（更改一个函数，而非随机字节），这极大地减少了浪费的评估器调用。

评估器反过来捕获LLM的幻想。LLM会自信地声明函数"在大O中是O(n log n)"，而它实际上是O(n^2)；挂钟基准测试解决了这个问题。

### AlphaEvolve在前沿技术栈中的位置

| 系统 | 生成器 | 评估器 | 领域 | 示例胜利 |
|---|---|---|---|---|
| AlphaEvolve | Gemini | 正确性 + 基准测试 | 算法、内核、调度器 | 48次乘法4x4矩阵乘法 |
| FunSearch (DeepMind, 2023) | PaLM / Codey | 正确性 | 组合数学 | 帽集下界 |
| AI Scientist v2 (Sakana, L5) | GPT/Claude | LLM评判 + 实验 | ML研究 | ICLR研讨会论文 |
| Darwin Godel Machine (L4) | 智能体脚手架 | SWE-bench / Polyglot | 智能体代码 | 20% → 50% SWE-bench |

四个都是相同配方的变体：生成器加评估器，循环。差异是评估器评分的内容及其严谨程度。

## 动手实践

`code/main.py` 在玩具符号回归问题上实现最小化的AlphaEvolve风格循环。"LLM"是一个提出对计算目标函数的程序进行小规模句法突变的stdlib代理。"评估器"测量保留测试点上的均方误差。

观察：

- 最佳分数如何随世代改进。
- MAP-elites网格如何保持多样化解决方案存活，使循环不会收敛到局部最小值。
- 移除保留测试（仅训练评估器）如何使循环显著过拟合。

## 产出成果

`outputs/skill-evaluator-rigor-audit.md` 是在新领域考虑AlphaEvolve风格循环的先决条件：你的评估器是否真正捕获了你关心的失败？

## 练习题

1. 运行 `code/main.py`。注意最佳分数轨迹。禁用保留评估器（标志 `--no-holdout`）并重新运行。量化过拟合。

2. 阅读AlphaEvolve论文第3节关于MAP-elites网格的内容。为新问题（例如编译器优化遍）设计一个会保持搜索多样性的特征向量描述符。

3. 48次乘法的4x4结果在56年后超越了Strassen的49次乘法界限。阅读论文附录F，用三句话解释为什么该问题的评估器特别容易正确，以及为什么大多数领域不是这样。

4. 提出一个AlphaEvolve会失败的领域。精确定位评估器在哪里断裂以及原因。

5. 对于你了解的一个领域，写下你会使用的评估器签名。包括(a)正确性条件，(b)性能指标，(c)保留输入生成规则，(d)至少一个反奖励黑客检查。

## 关键术语

| 术语 | 人们怎么说 | 实际含义 |
|---|---|---|
| AlphaEvolve | "DeepMind的进化编码智能体" | Gemini + 程序数据库 + 机器可检查评估器 |
| MAP-elites | "多样性保留存档" | 按特征向量键控的网格；每个单元格保存具有该描述符的最佳变体 |
| 岛屿模型 | "并行进化亚群" | 定期迁移的独立种群；防止过早收敛 |
| 机器可检查评估器 | "确定性预言机" | 单元测试、模拟器或LLM无法伪造的基准测试——此循环的先决条件 |
| 奖励黑客 | "优化测量而非目标" | 循环找到一种方法在不执行预期任务的情况下最大化分数 |
| 种子程序 | "起点" | 循环进化的初始正确但次优程序 |
| 保留评估器 | "LLM从未见过的评估数据" | 评估时生成的输入以防止记忆 |
