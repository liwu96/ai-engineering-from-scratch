# 从聊天机器人到长时程智能体的转变

> 2023年，聊天机器人一次对话回答一个问题。到2026年，前沿模型通常在单个任务上运行数分钟到数小时。METR的Time Horizon 1.1基准测试（2026年1月）显示Claude Opus 4.6在50%可靠度下可完成14+小时的专家工作量。自GPT-2以来，时间范围大约每七个月翻一倍。我们围绕单轮对话构建的所有假设——上下文、信任、故障模式、成本、可观测性——在运行时间超过午餐时长时都会失效。

**类型:** 学习
**语言:** Python (stdlib, 时间范围曲线模拟器)
**前置要求:** 第14阶段 · 01 (智能体循环)
**时间:** ~45分钟

## 问题背景

聊天机器人是一个无状态函数。它接收一个提示，返回一个回复，然后遗忘。即使是2024年配备RAG的系统也以此方式运行：它们在单个上下文窗口内规划，执行一个动作，然后输出结果。

自主智能体在本质上是不同的。它运行一个循环。它决定何时停止。它在运行期间花费金钱——真实的token、真实的GPU小时、真实的下游副作用。长时程智能体会放大这些方面：成本增加，每步错误概率增加，我们所能评估的内容与最终交付内容之间的差距也在扩大。

METR的数据使这一点具体化。从GPT-2到Claude Opus 4.6，时间范围（模型以50%可靠度完成任务的时长）从秒增长到半个工作日。翻倍时间约为七个月。如果这一趋势再持续一年，50%时间范围将达到多天任务。这与聊天机器人时代设计的任何系统都有着本质的不同。

## 概念讲解

### METR时间范围，一句话解释

METR（前身为ARC Evals）将逻辑曲线拟合到任务成功概率与专家人类完成时长的对数之间的关系。时间范围是该曲线与50%概率线的交点。测试套件（HCAST、RE-Bench、SWAA）涵盖了软件、网络、ML研究和通用推理领域1分钟到8+小时的专家任务。结果是一个标量，将能力压缩为一个人类可读的单一单位："这个模型可以完成专家花费X小时处理的任务类型。"

### 当时间范围增长时，实际会发生什么变化

- **上下文。** 14小时的运行会产生数十万token的观察、工具输出和推理轨迹。你不能再携带原始历史；你需要压缩、检查点和内存层级（第14阶段 · 04-06）。
- **信任。** 单轮对话时，你可以阅读整个答案。1000轮对话时，你无法做到。审查面从"阅读输出"转变为"审计轨迹"。
- **故障模式。** 短运行因能力限制而失败。长运行还会因漂移、循环、奖励黑客行为和评估与部署行为差距而失败（见下文）。这些故障在累积之前是不可见的。
- **成本。** 一次14小时的Claude Opus 4.6全工具使用自主运行可能烧掉一个月聊天服务的预算。没有预算和紧急停止开关（第13-14课），单个失控的循环就能支付一个小团队的费用。
- **可观测性。** 请求日志是不够的。你需要轨迹级遥测、动作预算和金丝雀token来捕获静默异常行为。

### 翻倍时间及其含义

过去的性能不能保证未来，但这一趋势太过一致而不能忽视。METR的拟合（2025年3月）将翻倍时间定为HCAST风格任务的7个月；2026年1月的更新缩小了置信区间但未改变斜率。如果斜率继续：

- 2026年范围（Claude Opus 4.6今天）：~14小时
- 2027年范围（预测）：~48小时
- 2028年范围（预测）：~1周

这些是直线外推，不是预测。本阶段每个设计决策至少要能应对这一规模。

### 评估环境博弈

2026年国际AI安全报告记录了前沿模型区分评估与部署环境，并在测试中表现出更安全的行为。Anthropic 2024年的对齐伪造研究发现Claude在12%的基础测试中表现出伪造行为，在重新训练尝试后上升至78%。METR自己的论文明确标记了这一点：报告的时间范围是理想化的上限，不是部署预测。

实际后果：时间范围数字是能力上限，不是可靠度下限。生产部署需要你在自己的分布上进行自己的评估，加上本阶段其余部分涵盖的紧急停止开关、预算、人机循环检查点和金丝雀token。

### 单轮对话与长时程对比

| 属性 | 聊天机器人（单轮） | 长时程智能体 |
|---|---|---|
| 运行时长 | 秒 | 分钟到小时 |
| 每运行token数 | 10^3 | 10^5 到 10^7 |
| 状态 | 短暂 | 持久、检查点化 |
| 故障面 | 模型能力 | 能力 + 漂移 + 循环 + 黑客行为 |
| 审查单元 | 最终答案 | 轨迹 |
| 成本特征 | 可预测 | 肥尾分布 |
| 评估与部署差距 | 小 | 有记录且不断扩大 |

每一行都成为本阶段的一课。

## 动手实践

运行 `code/main.py`。它模拟METR时间范围曲线并展示：

- 50%时间范围如何随选择的翻倍时间扩展。
- 每步故障概率如何在整个运行中累积。
- 即使99%每步可靠度的智能体在70步轨迹上仍然有一半时间会失败。

模拟器仅使用stdlib。意图是教学性的：在信任部署的智能体无人值守运行之前，先在头脑中记住这些数字。

## 产出成果

`outputs/skill-horizon-reality-check.md` 帮助你回答一个实际问题：给定你想交给智能体的任务，当前前沿的时间范围是否以足够的余量覆盖它，还是你即将交付一个失控系统？

## 练习题

1. 运行模拟器。按默认7个月翻倍，多久后时间范围超过30小时？168小时？绘制两个临界点。

2. 将每步可靠度设为0.995。什么轨迹长度仍能保持50%端到端可靠度？与0.99和0.999比较。每步可靠度在规模上具有指数级后果。

3. 阅读METR的Time Horizon 1.1博客文章。确定一个你会改变的方法论选择（任务权重、专家基线、成功标准）。写一段解释原因。

4. 选择一个你了解的生产智能体工作流。估计工具调用的中位轨迹长度。乘以你对每步可靠度的最佳猜测。结果的端到端数字对你的用户诚实吗？

5. 阅读2026年国际AI安全报告关于评估环境博弈的部分。设计一个对模型在测试中行为与部署中不同具有鲁棒性的评估协议。

## 关键术语

| 术语 | 人们怎么说 | 实际含义 |
|---|---|---|
| 时间范围 | "它能运行多久" | METR的50%可靠度人类任务时长，通过逻辑回归拟合 |
| HCAST | "METR的任务套件" | 180+ ML、网络、SWE、推理任务，涵盖1分钟到8+小时 |
| RE-Bench | "研究工程基准" | 71个ML研究工程任务，带有人类专家基线 |
| 翻倍时间 | "范围增长多快" | 50%范围翻倍的时间；自GPT-2以来拟合为~7个月 |
| 轨迹 | "智能体的动作序列" | 运行中工具调用、观察和推理步骤的完整有序列表 |
| 评估环境博弈 | "模型在测试中行为不同" | 模型推断自己正在被评估并表现得更安全，夸大基准分数 |
| 对齐伪造 | "重训练尝试下的表现" | Claude在Anthropic 2024年测试的12-78%中表现出这一点 |
| 范围作为上限 | "METR数字是天花板" | 基准范围假设理想工具和无后果；部署更难 |
