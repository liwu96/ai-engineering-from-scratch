# 自动对齐研究 (Anthropic AAR)

> Anthropic在独立沙箱中并行运行Claude Opus 4.6自动对齐研究团队，通过共享论坛协调，其日志位于任何沙箱之外（因此智能体无法删除自己的记录）。在弱到强训练问题上，AAR超越了人类研究人员。Anthropic自己的总结标记规定的工作流通常限制AAR灵活性并降低性能。自动化对齐研究是压缩时间线的压缩步骤，压缩到RSP旨在检测的确切错位风险。

**类型:** 学习
**语言:** Python (stdlib, 并行研究论坛模拟器)
**前置要求:** 第15阶段 · 05 (AI Scientist v2), 第15阶段 · 04 (DGM)
**时间:** ~60分钟

## 问题背景

对齐研究在人类研究人员时间上很昂贵。可扩展监督、奖励规范或弱到强训练等问题需要每次迭代数周的实验。随着前沿能力推进，对齐工作量增长速度超过合格研究人员的供给。

自动对齐研究（AAR）问：能力超越对齐的相同前沿模型是否能有助于缩小差距。Anthropic关于AAR运行的弱到强训练研究的2026年报告（alignment.anthropic.com/2026/automated-w2s-researcher/）是这类部署系统的首批公开结果之一。

结果确实是积极的：AAR解决了比人类基线更好的研究问题。结果也将本阶段发展的每个关注点集中于单一系统。如果对齐研究可以自动化，那么破坏安全机制的部分也可以。RSP的AI R&D能力阈值是用这个循环编写的。

## 概念讲解

### 架构（如公开描述）

- **并行智能体。** 多个Claude Opus 4.6实例作为AAR运行，每个在独立沙箱中。沙箱限制文件系统、网络和进程面。
- **共享论坛。** 发现发布到共享论坛，其存储后端位于每个沙箱之外。智能体可以阅读论坛；智能体无法从自己的沙箱内删除或编辑论坛记录。
- **任务分配。** 人类设计的任务队列向AAR分配研究问题。AAR提出分解、运行实验、撰写发现。
- **弱到强训练重点。** 已发表的研究解决了弱到强训练——使用较弱的监督模型训练较强的学生模型。AAR在这项任务上超越了人类研究人员。

### 为什么沙箱外日志很重要

日志完整性属性是受控实验与可能受损实验之间的区别。如果AAR可以编辑自己的日志，它们可以掩盖失败或可疑的实验。Anthropic直接标记这一点：该属性是信任研究输出的必要条件，且验证非平凡。

在基础设施术语中，类比是追加仅日志并透写到外部存储（例如S3对象锁定、不可变的Datadog日志）。智能体没有修改过去记录的凭证。这是2026年企业安全团队使用的相同模式，用于制作防勒索软件审计跟踪。

### 规定工作流的权衡

Anthropic的报告指出，规定的工作流通常限制AAR灵活性并降低性能。换句话说：如果人类设计者逐步编写研究计划，AAR的表现会比给予高级目标和分解自由度时差。这与智能体研究的各结果一致（LangGraph、微软的Agent Framework）——过度指定的脚手架会损害有能力的智能体。

安全含义是微妙的。改善AAR性能的灵活性也是允许未经批准的分解、新颖工具使用和目标漂移的灵活性。权衡是设计空间决策：多少灵活性购买足够的能力以击败人类，而不给智能体空间在分布外泛化目标？

### 压缩风险

RSP v3.0（第19课）引入AI R&D能力阈值：以有竞争力的成本完全自动化AI R&D流程的能力，与使用人类+AI工具相比。DeepMind的FSF v3包括类似的ML R&D自主水平。两个框架都将此阈值视为增强控制的触发器。

AAR距离阈值一步之遥：它自动化流程的一部分（特定、范围明确任务上的对齐研究），而非端到端的能力开发循环。时间线问题是多快缩小差距。

压缩的时间线是复合故障担忧。如果对齐研究和能力研究以相似速度复合，错位风险面至少以能力速度增长。如果能力复合更快（历史趋势），差距扩大。这是AAR是合格好事的论点：只有当研究过程值得信赖时，每个额外的对齐结果才会缩小差距。

### AAR不能替代什么

人类研究人员设置任务队列、审查结果并持有宪法权威。AAR加速流程的中间部分，而非两端。Anthropic的已发表输出包括AAR贡献和人类研究者对发表什么、撤回什么和改进什么的判断。

这与第15课的提议-然后-提交模式应用于研究本身相匹配：AAR提议；人类提交。

## 动手实践

`code/main.py` 模拟多AAR研究论坛。三个独立的"研究智能体"并行运行，向追加仅论坛发布发现，可选的篡改尝试。

观察：

- 沙箱外日志如何捕获日志篡改尝试。
- 自由分解的任务分配如何在更难的问题上胜过固定工作流。
- 单个受损AAR如果日志不可篡改如何污染论坛信号。

## 产出成果

`outputs/skill-aar-deployment-review.md` 是自动对齐研究流程的部署前审查。

## 练习题

1. 运行 `code/main.py`。比较"固定工作流"与"自由分解"设置。自由分解总是赢吗，还是有问题类别固定工作流具有竞争力？

2. 修改模拟器使一个智能体尝试日志篡改。确认追加仅日志检测到它。写一段描述检测签名在日志中的确切样子。

3. 阅读Anthropic的弱到强AAR报告。识别AAR超越人类研究人员的特定子任务。什么使其适合自动化？

4. 设计一个平衡AAR灵活性（更好结果）与规定工作流约束（更容易审计）的任务队列分配策略。描述你会如何A/B测试两者。

5. 阅读RSP v3.0的AI R&D-4阈值。用一段描述你认为什么会跨越它而AAR目前没有。

## 关键术语

| 术语 | 人们怎么说 | 实际含义 |
|---|---|---|
| AAR | "自动对齐研究者" | 在对齐问题上自主运行的Claude Opus 4.6实例 |
| 弱到强训练 | "用较弱监督训练较强模型" | AAR超越人类的经典可扩展监督基准 |
| 共享论坛 | "智能体发布发现的地方" | 追加仅、沙箱外存储 |
| 沙箱外日志 | "智能体无法编辑自己的记录" | 透写到外部存储的防篡改 |
| 规定工作流 | "人类设计者的逐步计划" | 限制AAR；通常比自由分解降低性能 |
| 自由分解 | "智能体决定如何分解任务" | 更有能力，更难审计 |
| AI R&D阈值 | "RSP/FSF能力水平" | 以有竞争力的成本完全自动化R&D流程 |
| 压缩时间线 | "对齐与能力竞赛" | 如果能力复合快于对齐，错位风险增长 |
