# 动作预算、迭代上限和成本治理器

> 一个中型电子商务智能体在团队启用"订单跟踪"技能后，月度LLM成本从$1,200跃升至$4,800。这不是定价错误。这是一个发现新循环并在其中持续消费的智能体。微软的智能体治理工具包（2026年4月2日）将防御此类编码化：每请求 `max_tokens`、每任务token和美元预算、每天/每月上限、迭代上限、分层模型路由、提示缓存、上下文窗口、昂贵动作上的人机循环检查点、预算突破时的紧急停止开关。Anthropic的Claude Code Agent SDK在不同名称下发布相同原语。财务速度限制——例如10分钟内>$50切断访问——比每月上限更快捕获循环。

**类型:** 学习
**语言:** Python (stdlib, 分层成本治理器模拟器)
**前置要求:** 第15阶段 · 10 (权限模式), 第15阶段 · 12 (持久执行)
**时间:** ~60分钟

## 问题背景

自主智能体在每轮上花费真金白银。聊天机器人的不良输出是坏回复；智能体的不良循环是账单。行业文档化的故障模式术语是"钱包拒绝服务"——智能体持续推理、持续工具调用、持续计费，无事阻止它因为未设计阻止。

修复不是一个数字。它是不同时间尺度和粒度上的限制堆栈：每请求、每任务、每小时、每天、每月。设计良好的堆栈在几分钟内捕获失控循环，几小时内捕获缓慢泄漏，一天内捕获不良发布。相同堆栈在长时程自主时保持预算。

这是工程课：数学是平凡的，纪律是团队失败的地方。下面的限制列表都在微软智能体治理工具包或Anthropic Claude Code Agent SDK文档中命名。

## 概念讲解

### 成本治理器堆栈

1. **每请求 `max_tokens`。** 简单。防止任何单次调用产生无界完成。
2. **每任务token预算。** 整个运行中不超过N个token。上限时硬停止。
3. **每任务美元预算。** 与token相同但以货币计算。Claude Code中的 `max_budget_usd`。
4. **每工具调用上限。** 不超过N次 `WebFetch` 调用、N次 `shell_exec` 调用等。
5. **迭代上限 (`max_turns`)。** 智能体循环总迭代次数；防止无限推理循环。
6. **每分钟/每小时/每天/每月上限。** 滚动窗口。在不同时间尺度捕获泄漏。
7. **财务速度限制。** 例如"如果10分钟内花费超过$50，切断访问"。在每月上限触发前捕获基于循环的消耗。
8. **分层模型路由。** 默认为较小模型；仅当分类器判断任务需要时才升级到较大模型。
9. **提示缓存。** 系统提示和稳定上下文存储在提供商缓存中；重新发送的token成本接近零。
10. **上下文窗口。** 压缩/摘要以保持活动上下文低于阈值；直接token成本降低。
11. **昂贵动作上的人机循环检查点。** 在已知昂贵的动作（长工具调用、大下载、昂贵的模型升级）前，需要人工点击。
12. **预算突破时的紧急停止开关。** 任何上限触发时会话中止。记录上限；需要单独的重启路径。

### 为什么是堆栈，而非单一上限

单一每月上限仅在钱包消失后捕获失控智能体。单一每请求上限在会话级别不捕获任何内容。不同故障模式需要不同时间尺度：

- **失控循环**（智能体卡在5秒重试中）：由速度限制捕获。
- **缓慢泄漏**（智能体每项任务做~2倍预期工作）：由每日上限捕获。
- **不良发布**（新版本使用5倍token）：由每周/每月上限捕获。
- **合法激增**（真实需求，非错误）：由小时/天上限捕获并清晰记录。

### Claude Code的预算面

Claude Code Agent SDK公开（公共文档）：

- `max_turns` — 迭代上限。
- `max_budget_usd` — 美元上限；突破时会话中止。
- `allowed_tools` / `disallowed_tools` — 工具允许列表和拒绝列表。
- 工具使用前自定义成本核算的钩子点。

与权限模式阶梯（第10课）结合。没有 `max_budget_usd` 的 `autoMode` 会话是无治理的自主性。Anthropic明确将自动模式框架化为需要预算控制；分类器与成本正交。

### EU AI法案、OWASP Agentic Top 10

微软的智能体治理工具包涵盖OWASP Agentic Top 10和EU AI法案第14条（人类监督）要求。对于欧盟的生产，日志记录和上限强制执行不是可选的。

### 观察到的 $1,200 → $4,800 案例

微软文档中的真实案例：电子商务智能体在添加新工具后月度成本翻三倍。工具允许智能体在每次会话期间轮询订单状态。无循环检测。无每工具上限。无周增长警报。修复是每工具上限加每日增长警报。这是模板：每个新工具面是新的潜在循环；每个新工具需要自己的上限和自己的警报。

## 动手实践

`code/main.py` 模拟有和没有分层成本治理器堆栈的智能体运行。模拟智能体在若干轮后漂入轮询循环；分层堆栈在速度窗口内捕获它，而单一每月上限要到几天后才触发。

## 练习题

1. 运行 `code/main.py`。确认在轮询循环轨迹上速度限制在迭代上限前触发。现在禁用速度限制并测量迭代上限捕获前智能体"花费"多少。

2. 为浏览器智能体（第11课）设计每工具上限集。哪个工具需要最紧的上限？哪个工具可以无风险无界运行？

3. 阅读微软智能体治理工具包文档。列出工具包命名的每种上限类型。将每种映射到一种故障模式（失控循环、缓慢泄漏、不良发布、激增）。

4. 为真实任务（例如"分类仓库中50个问题"）的隔夜无人值守运行定价。将 `max_budget_usd` 设在2倍点估计。证明2倍。

5. Claude Code的 `max_budget_usd` 在会话总成本时触发。设计你会外部执行的补充速度限制。什么触发切断，重启是什么样？

## 关键术语

| 术语 | 人们怎么说 | 实际含义 |
|---|---|---|
| 钱包拒绝服务 | "失控账单" | 无上限停止时产生消费的智能体循环 |
| max_tokens | "每请求上限" | 单次完成大小的上限 |
| max_turns | "迭代上限" | 会话中智能体循环迭代的上限 |
| max_budget_usd | "美元紧急停止开关" | 会话成本上限；突破时中止 |
| 速度限制 | "速率上限" | 短窗口上的消费限制（例如$50/10分钟） |
| 分层路由 | "小模型优先" | 便宜模型默认；仅当分类器需要时才升级 |
| 提示缓存 | "缓存系统提示" | 提供商端缓存将重新发送token成本降低到接近零 |
| 人机循环检查点 | "人工批准门" | 昂贵动作前需要人工点击 |
