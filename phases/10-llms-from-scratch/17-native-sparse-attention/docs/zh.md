# 原生稀疏注意力 (DeepSeek NSA)

> 在6.4万 Token 时，注意力消耗70-80%的解码延迟。每个开源模型实验室都有一个修复计划。DeepSeek 的 NSA (ACL 2025 最佳论文) 是最终坚持下来的方案：三个并行注意力分支——压缩的粗粒度 Token、选择性保留的细粒度 Token 和用于局部上下文的滑动窗口——通过一个学习的门控组合。它是硬件对齐的（内核友好）、原生可训练的（在预训练中工作，不是在推理时附加），在6.4万 Token 解码上它比 FlashAttention 运行得更快，同时匹配或超越全注意力的质量。本课程端到端构建三个分支并展示为什么稀疏性是端到端可微分的。

**类型:** 构建
**语言:** Python (stdlib)
**前置要求:** 第7阶段·12 (KV 缓存, flash-注意力)，第7阶段·15 (注意力变体)，第10阶段·16 (差分注意力)
**时间:** ~60分钟

## 学习目标

- 说明 NSA 的三个注意力分支及其各自捕获的内容。
- 解释为什么 NSA 是"原生可训练的"而之前的稀疏注意力方法只能是推理时使用的。
- 计算在6.4万 Token 上下文时 NSA 与全注意力的注意力计算节省，作为压缩块大小和选择 top-k 的函数。
- 在短合成序列上用 stdlib Python 实现三分支组合并验证门控权重行为。

## 问题背景

在序列长度 N 时，全注意力花费 `O(N^2)` 时间和每层 `O(N)` KV 缓存。在6.4万 Token 时，计算和内存带宽数字是灾难性的。来自 NSA 论文的测量理论估计：在6.4万 Token 时，注意力占总解码延迟的70-80%。所有下游指标——TTFT、每秒 Token 数、每百万 Token 成本——都由注意力成本主导。

稀疏注意力是显而易见的答案。之前的尝试分为两类。固定模式稀疏性（滑动窗口、步进、块局部）丢弃信息并在长程召回任务上失败。推理时稀疏性（KV 缓存剪枝、H2O、StreamingLLM）应用于在稠密注意力上预训练的模型，只能恢复潜在加速的一小部分，因为模型从未被要求通过稀疏模式路由信息。

原生稀疏注意力 (Yuan et al., DeepSeek + PKU + UW, ACL 2025 最佳论文, arXiv:2502.11089) 两者兼顾：模型在预训练期间学习的稀疏性模式，实现为在推理时实际交付计算节省的内核对齐算法。两年后，NSA 或直接后代将是每个前沿长上下文模型的默认注意力。

## 概念讲解

### 三个并行分支

对于每个查询，NSA 运行注意力三次，针对 KV 缓存的三个不同视图：

1. **压缩分支。** Token 被分组为大小 `l` 的块（通常为32或64）。每个块通过一个小型学习的 MLP 压缩成单个摘要 Token。查询在这些压缩 Token 上关注，获得整个序列的粗粒度视图。

2. **选择分支。** 使用压缩分支的注意力分数，识别与当前查询最相关的 top-k 块。读取这些块的细粒度（未压缩）Token，查询在所有 Token 上关注。将压缩分支注意力视为路由信号的选择。

3. **滑动窗口分支。** 查询关注最近的 `W` 个 Token（通常为512）以获取局部上下文。该分支捕获其他两个可能错过的结构繁重的短程模式（语法、局部共指）。

三个分支输出通过学习的每位置门控组合：

```
out = g_cmp * out_cmp + g_sel * out_sel + g_win * out_win
```

`g_cmp, g_sel, g_win` 是来自查询上小型 MLP 的门控权重。它们不必求和为1——可以独立加权分支。

### 为什么这是"原生可训练的"

选择步骤（top-k 块）是离散的。离散操作破坏梯度流。之前的稀疏注意力工作要么跳过选择的反向传播（限制训练），要么使用在推理时不给出真实稀疏性的连续松弛。

NSA 避开这一点：压缩分支注意力 IS 在整个序列上的可微分粗粒度注意力。Top-k 操作只是重用压缩分支的最高注意力分数来选择加载哪些细粒度块。梯度流经压缩分支分数（影响压缩输出 AND 选择逻辑），选中块对最终输出的贡献也是可微分的。不可微分的 `top_k` 操作在前向计算图上是无操作——它只控制从内存加载哪些块。

这就是 NSA 可以端到端用于预训练的原因。模型联合学习通过三个分支路由信息，产生在推理时实际交付承诺加速的稀疏模式。

### 硬件对齐内核

NSA 的内核是为现代 GPU 内存层次结构设计的。内核按 GQA 组加载查询（外循环），为每组获取相应的稀疏 KV 块（内循环），并在 SRAM 上运行注意力。因为每个查询组看到相同的选中块（选择是按查询组而非按查询头），KV 加载在组内摊销。算术强度保持高位。

论文报告 Triton 内核在6.4万 Token 解码上比 FlashAttention 快9倍，加速比随序列长度增长。提供前向和后向内核。

### 计算预算

令 `N` 为序列长度，`l` 为压缩块大小，`k` 为 top-k 选择计数，`w` 为滑动窗口，`b` 为选中块大小（通常等于 `l`）。

- 压缩分支：每查询 `O(N/l)` 个键，所以总共 `O(N * N / l)`。
- 选择分支：每查询 `O(k * b)` 个键，所以总共 `O(N * k * b)`。
- 滑动分支：每查询 `O(w)` 个键，所以总共 `O(N * w)`。

总计：`O(N * (N/l + k*b + w))`。

当 `N = 64k, l = 64, k = 16, b = 64, w = 512` 时：每查询成本为 `1000 + 1024 + 512 = 2536 个键`。全注意力为 `64000 个键`。25倍计算减少。

当 `N = 128k, l = 64, k = 16, b = 64, w = 512` 时：每查询成本为 `2000 + 1024 + 512 = 3536 个键`。全注意力为 `128000 个键`。36倍减少。收益随序列长度增长，这正是重点。

### 比较

| 方法 | 可微分 | 真实推理加速 | 长程召回 |
|------|-------|------------|---------|
| 仅滑动窗口 | 是 | 是 | 失败 |
| 步进/块稀疏 | 是 | 是 | 部分 |
| KV 剪枝 (H2O, StreamingLLM) | N/A (推理时) | 是 | 部分 |
| MoBA (Moonshot) | 部分 | 是 | 良好 |
| NSA | 是 (原生) | 是 (6.4万 Token 时9倍) | 匹配全注意力 |

MoBA (Moonshot, arXiv:2502.13189) 同时发表并采取类似的三合一方法，将 MoE 原则应用于注意力块。NSA 和 MoBA 是2026年长上下文预训练需要了解的两种架构。

## 动手实践

`code/main.py` 在短合成序列上实现三个分支并展示：

- 压缩 MLP（为教学清晰使用简单均值池基线；真实 NSA 使用学习的 MLP）。
- 由压缩分支分数驱动的 top-k 块选择。
- 最后 `w` 个 Token 的滑动窗口注意力。
- 门控组合。
- 与全注意力相比的计算计数打印。

### 步骤1：将 Token 压缩成块

```python
def compress(K, l):
    n = len(K)
    n_blocks = (n + l - 1) // l
    out = []
    for b in range(n_blocks):
        start, end = b * l, min((b + 1) * l, n)
        block = K[start:end]
        summary = [sum(row[d] for row in block) / len(block) for d in range(len(K[0]))]
        out.append(summary)
    return out
```

### 步骤2：压缩分支注意力

在查询和压缩键上运行 softmax 注意力。压缩分支分数兼作 top-k 选择的信号。

### 步骤3：top-k 块选择

挑选 `k` 个最高得分压缩块的索引。从这些块加载原始未压缩 Token 并在其上运行注意力。

### 步骤4：滑动窗口注意力

取最后 `w` 个 Token 并在其上运行标准注意力。

### 步骤5：门控 + 组合

查询上的小型 MLP 产生三个门控权重。最终输出是三个分支输出的加权和。

### 步骤6：计算计数

打印每查询每个分支关注的键数和总数。与 `N`（全注意力）比较。在 `l = 32, k = 4, w = 128` 的1024 Token 合成数据上，NSA 每查询看到 `32 + 128 + 128 = 288` 个键，而全注意力为1024——3.5倍减少。

## 实际应用

NSA 正在 DeepSeek 自己的长上下文预训练流水线中发布。截至2026年4月在公共推理堆栈中的集成状态：

- **DeepSeek 内部**：原生，发布的权重使用 NSA 或其后续 DSA (Deepseek Sparse Attention)。
- **vLLM**：正在开发中对 DeepSeek-V3.x 权重的实验性 NSA 支持。
- **SGLang**：已发布 NSA 基准；生产路径跟随 vLLM。
- **llama.cpp / CPU**：不支持；内核分解的开销在 CPU 吞吐量下不值得。

何时使用 NSA：

- 针对64k+ 上下文的预训练或持续训练运行，有充足的计算预算。
- DeepSeek 自己长上下文检查点的推理。权重是 NSA 原生的。

何时不使用：

- 服务现有的稠密注意力预训练模型。你无法在不进行持续训练的情况下改装 NSA。
- 上下文小于16k。三分支开销主导节省。
- 批次1交互式聊天。延迟敏感解码受益，但仅在长上下文时。

## 关键术语

| 术语 | 人们怎么说 | 实际含义 |
|------|-----------|---------|
| 压缩分支 | "粗视图" | 在块平均键上的注意力，每查询以 O(N/l) 个键提供全局上下文 |
| 选择分支 | "Top-k 块" | 在具有最高压缩分支分数的 `k` 个块上的细粒度注意力 |
| 滑动窗口 | "局部上下文" | 在最后 `W` 个 Token 上的注意力用于短程模式 |
| 原生可训练性 | "预训练时启用稀疏性" | 稀疏性模式在预训练期间学习，不是在推理时附加的 |
| 压缩块大小 l | "粗视图的组大小" | 多少个 Token 合并成一个摘要；典型32-64 |
| Top-k | "保留的块" | 其未压缩 Token 被读取的压缩块数量；典型16 |
| 滑动窗口 W | "局部注意力半径" | 典型512；更短伤害局部连贯性，更长浪费计算 |
| 分支门控 | "如何混合三个" | 每位置 MLP 输出，加权三个分支的贡献 |
| 硬件对齐 | "内核友好稀疏性" | 选择的稀疏性模式使实际 GPU 内核实现理论加速 |
| DSA | "NSA 的后续" | Deepseek Sparse Attention，DeepSeek 系列中跟随 NSA 的架构 |
