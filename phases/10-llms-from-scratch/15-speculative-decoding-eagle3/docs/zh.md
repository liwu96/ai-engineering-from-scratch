## 学习目标

- 用一句话陈述 Leviathan 定理并证明推测循环产生的样本与验证器分布相同。
- 回顾从原始推测解码（Leviathan 2023）到 EAGLE、EAGLE-2 和 EAGLE-3 的两年进展，并指出每一步消除的确切限制。
- 从接受率 `α` 和草稿到验证器成本比 `c` 计算预期加速比，并为每种情况选择最佳草稿长度 `N`。
- 从零实现完整的推测循环：草稿、验证、从残差拒绝采样、拒绝时回滚 KV 缓存、完全接受时发出奖励 Token。

## 问题背景

在70B模型上的自回归解码在 H100 上可能每秒35个 Token。GPU 远未达到饱和。内存带宽是瓶颈：每个 Token 从 HBM 加载70B权重，做一步算术，产生一个浮点数。计算单元大部分时间空闲。

推测解码将其转化为一个你可以实际解决的吞吐量问题。一个廉价的草稿用 `N` 次小型前向传递提议 `N` 个 Token。验证器对前缀加所有 `N` 个草稿运行一次。如果验证器在位置 `i` 的分布与草稿一致（我们将使其精确的统计意义），我们接受；否则，我们拒绝并从残差分布采样一个修正。单次大模型前向传递产生最多 `N+1` 个接受 Token，而非一个。

重要的定理是 Leviathan, Kalman, Matias（ICML 2023）：输出分布与直接从验证器采样产生的分布相同。不是近似。完全相同。这就是推测解码在生产中可接受的全部原因——它是纯粹的延迟优化，没有质量权衡。

第7阶段·第16课给你的是数学。本课程给你的是训练堆栈。好的草稿比廉价草稿值得2倍以上的加速。EAGLE、EAGLE-2 和 EAGLE-3（Li et al., 2024–2025）将"草稿 = 相同模型的较小版本"转变为精确的工程学科。2026年生产推理服务器默认使用 EAGLE-3。

## 概念讲解

### 不变量：Leviathan 拒绝采样

令 `p(t)` 为给定某个前缀时草稿对下一个 Token 的分布，`q(t)` 为验证器的分布。从草稿采样 Token `d ~ p`。以概率 `min(1, q(d) / p(d))` 接受。拒绝时，从残差分布 `(q - p)_+ / ||(q - p)_+||_1` 采样。结果样本按 `q` 分布。无论 `p` 有多差——越差，拒绝越频繁，但输出保持精确。

将其中 `N` 个调用用一次验证器前向传递对 `prefix + d_1 + ... + d_N` 堆叠。验证器同时返回 `q_1, q_2, ..., q_{N+1}`。从左到右遍历。在位置 `j` 第一次拒绝时，从 `residual(q_j, p_j)` 采样并停止。完全接受时，从 `q_{N+1}` 采样一个奖励 Token。

### 什么决定加速比

令 `α` 为每草稿 Token 的预期接受率。令 `c = cost(草稿) / cost(验证器)` 为成本比。每验证器前向的预期接受 Token 数为：

```
E[接受] = (1 - α^(N+1)) / (1 - α)
```

每接受 Token 的预期总墙钟时间为 `(N * c + 1) / E[接受]`。相对于 `N` 最小化，你得到最佳点。对于 `α = 0.8, c = 0.05`：最佳 `N` 约为5-7，加速比为3.2倍。对于 `α = 0.95, c = 0.02`：最佳 `N` 约为8-10，加速比接近5倍。

单个最大的杠杆是 `α`。从 `α = 0.6`（原始草稿）到 `α = 0.9`（EAGLE-3）在固定 `N = 5` 下，每验证器前向的预期接受 Token 从2.2个变为4.1个。相同验证器下几乎2倍的吞吐量。

### 两年进展

**原始推测（Leviathan, 2023）。** 草稿模型是来自同一家族的独立训练的小型 LLM。易于接入，`α ≈ 0.6`，最佳加速比约2倍。

**EAGLE-1（Li et al., 2024）。** 草稿是一个微型 Transformer——通常一到两层——以验证器的最后一层隐藏状态为输入直接预测下一个 Token。因为草稿看到验证器的特征表示，其分布更接近验证器的。`α` 上升到0.7-0.8。

**EAGLE-2（Li et al., 2024）。** 添加动态草稿树：不提议单个 `N` Token 序列，而是提议一个小候选树，用一次前向传递（树注意力）由验证器评分每个候选，并遍历最高概率路径。草稿长度每步自适应。每接受路径 Token 的 `α` 上升到0.85以上。

**EAGLE-3（Li et al., 2025, NeurIPS）。** 两个更多改变。首先，完全放弃特征预测损失——EAGLE-1/2 训练草稿匹配验证器的隐藏状态，这限制了数据帮助的程度。EAGLE-3 直接在 Token 预测上训练。其次，训练时测试（TTT）：在草稿训练期间，将草稿自己的先前预测作为输入在多个步骤中反馈，与推理时相同。这使训练和测试分布对齐并阻止错误累积。实测加速比：聊天场景高达6.5倍，在 H100 上 SGLang 批次64时吞吐量提升38%。

### KV 缓存回滚

验证将验证器的 KV 缓存一次扩展 `N` 个条目。如果在位置 `j` 发生拒绝，位置 `j-1` 之后的缓存内容现在错了。两种常见实现：写入暂存缓冲区并在接受时提交（vLLM、TensorRT-LLM），或保持物理 KV 缓存加逻辑长度并在拒绝时截断。无论哪种方式，回滚成本是每层每头的字节数，与前向传递成本相比可忽略。

对于 EAGLE-2 树搜索，验证器使用尊重树拓扑的非因果掩码运行注意力。工程实现繁琐，但计算是使用自定义掩码的标准 flash-attention 调用。

### 2026年草稿架构

| 策略 | 草稿类型 | `α` | 加速比 | 训练成本 |
|------|---------|-----|--------|---------|
| 原始 | 独立小型 LLM | 0.55-0.70 | 1.8-2.3倍 | 无（复用现有小模型） |
| Medusa | 验证器上的额外 LM 头 | 0.65-0.75 | 2-3倍 | ~1B SFT Token |
| EAGLE-1 | 隐藏状态上的一层 Transformer | 0.70-0.80 | 2.5-3倍 | ~60B Token |
| EAGLE-2 | EAGLE-1 + 动态草稿树 | 0.80-0.88 | 3-4倍 | ~60B Token |
| EAGLE-3 | 多层特征融合 + TTT | 0.88-0.92 | 3.5-6.5倍 | ~60-200B Token |
| Lookahead | 无草稿（Jacobi 迭代） | N/A | 1.3-1.6倍 | 无 |

2026年生产环境：vLLM 和 SGLang 在有 EAGLE-3 时默认使用，否则使用 EAGLE-2。TensorRT-LLM 对 Meta 和 NVIDIA 公共模型有最快的 Medusa 路径。llama.cpp 为 CPU 部署提供原始草稿。

## 动手实践

见 `code/main.py`。这是完整的 Leviathan 推测循环，包含所有部分：N个草稿、验证器并行传递、每位置拒绝、残差采样、奖励 Token、KV 回滚，以及输出分布与直接从 `q` 采样匹配的实证验证。

### 步骤1：拒绝规则

```python
def accept(q_prob, p_prob, u):
    if p_prob <= 0:
        return True
    return u < min(1.0, q_prob / p_prob)
```

### 步骤2：残差分布

```python
def residual(q, p):
    raw = [max(0.0, qi - pi) for qi, pi in zip(q, p)]
    s = sum(raw)
    if s == 0:
        return list(q)
    return [r / s for r in raw]
```

### 步骤3：完整推测步骤

`spec_step` 函数从 `p` 起草 `N` 个 Token，然后在一次并行 `q` 评估中验证所有 Token。对于每个起草 Token，它应用拒绝规则，第一次拒绝时从残差采样修正。如果全部接受，它从 `q_{N+1}` 发出一个奖励 Token。

### 步骤4：KV 回滚记账

模拟器跟踪每个工作者的逻辑 `kv_length`。接受 `k` 个草稿时，`kv_length += k`。在位置 `j` 拒绝时，缓存已经写入 `j` 之后，但逻辑长度设置为 `prefix_length + j + 1`——修正 Token 之后一个。后续读取截断到逻辑长度。

### 步骤5：Leviathan 检查

运行50,000个推测步骤。计算接受 Token 的实证分布。与50,000个直接从 `q` 的样本比较。卡方统计量应远低于临界值。该定理在实践中成立。

### 步骤6：加速比 vs α

通过以不同幅度扰动 `p` 远离 `q` 来扫掠草稿质量。测量 `α`，然后绘制每验证器调用的预期 Token 作为 `α` 和 `N` 的函数。代码打印表格显示 EAGLE-3 类草稿质量（`α ≈ 0.9`）如何解锁每验证器调用4-5个 Token。

带 EAGLE-3 的生产级 `vllm serve`：

```bash
vllm serve meta-llama/Llama-3.3-70B-Instruct \
  --speculative-config '{
    "model": "yuhuili/EAGLE3-LLaMA3.3-Instruct-70B",
    "num_speculative_tokens": 5,
    "method": "eagle3"
  }'
```

在 H100 上 SGLang 批次64的 EAGLE-3：根据 EAGLE-3 论文，比批次64原始解码大约1.38倍吞吐量。

何时使用推测解码：

- 任何 p50 延迟比峰值吞吐量更重要的交互式聊天工作负载。
- 代码生成和结构化输出（JSON、SQL）。`α` 超过0.9，因为目标分布高度可预测。
- 长文本生成（数千 Token）。摊薄的加速比持续回报。

何时不使用：

- 非常小的模型（< 3B）。草稿没有比验证器便宜多少。
- 微小的批次1 CPU 部署。草稿模型的内存开销可能不值得。
- 温度很高的创意采样，`α` 崩溃的场景。

## 关键术语

| 术语 | 人们怎么说 | 实际含义 |
|------|-----------|---------|
| Leviathan 规则 | "min(1, q over p)" | 以概率 `min(1, q(d)/p(d))` 进行伯努利接受/拒绝，在拒绝时从残差采样可精确保留验证器分布 |
| 残差分布 | "(q减p)加，归一化" | `(q - p)_+` 在零处钳位并重新归一化——拒绝时从中采样的正确分布 |
| 接受率 α | "草稿多经常正确" | 拒绝规则下的预期每 Token 伯努利成功概率；支配所有加速比数学 |
| EAGLE-1 | "隐藏状态草稿" | 以验证器最后一层隐藏状态为条件的微型 Transformer 草稿（Li et al., 2024） |
| EAGLE-2 | "动态草稿树" | EAGLE-1 加上用一次验证器传递中的树注意力评分的候选延续树 |
| EAGLE-3 | "训练时测试" | 放弃特征预测损失，直接在草稿训练期间将草稿自己的输出反馈给它进行 Token 预测训练 |
| 训练时测试 (TTT) | "暴露偏差修复" | 在训练期间自回归运行草稿，使训练和测试输入分布匹配——计划采样的直接类比 |
| KV 回滚 | "撤销拒绝的草稿" | 拒绝后将验证器的 KV 缓存重置到接受前缀长度的记账 |
| 奖励 Token | "免费的那个" | 当所有 `N` 个草稿接受时，从 `q_{N+1}` 无额外验证器成本采样一个额外 Token |
| 树注意力 | "一次验证多个候选" | 使用尊重草稿树拓扑的非因果掩码的注意力；一次前向传递计算树中每个节点的 `q_i` |
