# 多 Token 预测 (MTP)

> 从 GPT-2 到 Llama 3 的每个自回归 LLM 在每个位置上训练一个损失：预测下一个 Token。DeepSeek-V3 在每个位置上添加了第二个损失：预测再下一个 Token。额外的140亿参数（在6710亿模型上）通过梯度流蒸馏回主模型，训练好的 MTP 头在推理时被重新用作推测解码草稿，接受率超过80%。1.8倍的生成吞吐量免费获得。本课程从 DeepSeek 技术报告构建顺序 MTP 模块，计算损失和共享头参数布局，并解释为什么 MTP 保持因果链而 Gloeckle et al. 的原始并行 MTP 破坏了它。

**类型:** 构建
**语言:** Python (stdlib)
**前置要求:** 第10阶段·04（预训练迷你 GPT），第10阶段·15（推测解码）
**时间:** ~60分钟

## 学习目标

- 陈述 MTP 训练目标并推导跨预测深度的联合损失。
- 解释 Gloeckle et al. 的并行 MTP 头（2024）和 DeepSeek-V3 的顺序 MTP 模块之间的区别，以及为什么顺序设计保持因果链。
- 计算将 MTP 模块添加到预训练运行的参数和内存开销。
- 从头实现一个 MTP 模块：共享嵌入、每深度 Transformer 块、投影和共享输出头。

## 问题背景

下一个 Token 预测是标准的 LLM 训练目标。每个隐藏状态被监督精确预测一件事：紧随其后的 Token。这是一个令人惊讶的弱信号。序列中大多数信息延伸到一个 Token 之外——结构、连贯性、事实性、算术流。模型必须通过数万亿个 Token 累积许多单 Token 信号来学习这些。

MTP 问：如果每个隐藏状态被监督一次性预测多个未来 Token 会怎样？Gloeckle et al. (Meta, 2024) 表明这有帮助。他们的实现在主干上放置了几个独立的输出头，每个预测不同的偏移。并行、简单，但头看到相同的隐藏状态没有任何层次细化——而且预测没有因果链式连接，因此它们不能用于推测解码。

DeepSeek-V3（2024年12月）将 MTP 重新设计为在每个预测深度保持因果链的顺序模块。模型从 `h_i^(0)` 预测 `t+1`，然后从新的隐藏状态 `h_i^(1)` 预测 `t+2`，该状态将 `h_i^(0)` 与 `E(t+1)` 嵌入结合，依此类推。每个深度是它自己的小型 Transformer 块。共享嵌入和共享输出头保持参数开销适中。在 DeepSeek-V3 的规模上，在6710亿主模型权重之上，MTP 模块有140亿额外参数。这2%的开销购买了更密集的训练信号 AND 推理时现成的推测解码草稿。

本课程从头构建单个 MTP 模块和 D 深度损失。数学很整洁。实现是150行。

## 概念讲解

### 顺序 MTP 方案

DeepSeek-V3 在主模型之上添加 `D` 个 MTP 模块。每个模块 `k`（对于 `k = 1..D`）预测深度 `k` 的 Token——即，给定前缀到位置 `i`，预测 `t_{i+k}`。

模块 `k` 包括：

- 一个带有自己注意力和 MLP 的 Transformer 块 `T_k`。
- 一个投影矩阵 `M_k`，将前深度的隐藏状态与下一深度的真实 Token 嵌入结合。
- 共享嵌入 `E`（与主模型相同）。
- 共享输出头 `Out`（与主模型相同）。

在训练时，对于前缀到位置 `i`，每深度的隐藏状态为：

```
h_i^(0) = 主模型主干在位置 i
h_i^(k) = T_k( M_k * concat(RMSNorm(h_i^(k-1)), RMSNorm(E(t_{i+k}))) )   对于 k >= 1
```

每深度的预测为：

```
logits_{i+k} = Out(h_i^(k-1))   对于 k = 1..D
```

每深度损失是与真实 `t_{i+k}` 的交叉熵：

```
L_k = CE(logits_{i+k}, t_{i+k})
```

跨深度的联合损失：

```
L_MTP = (lambda / D) * sum_{k=1..D} L_k
```

`lambda` 是一个小的加权因子——DeepSeek-V3 在前10%的训练中使用0.3，之后使用0.1。总训练损失是 `L_main + L_MTP`。

### 为什么是顺序而非并行

Gloeckle 的原始并行 MTP 有 D 个输出头，每个直接应用于 `h_i^(0)`。每个头从相同的主干隐藏状态预测 `t_{i+k}`。训练没问题，但预测不相互条件。你无法使用 `head_1` 的输出帮助 `head_2`——头并行触发。

DeepSeek-V3 的顺序设计从 `h_i^(k-1)` 加上实际下一 Token 嵌入 `E(t_{i+k})` 构建 `h_i^(k)`。这保持了因果链：要预测 `t_{i+k+1}`，深度 `k+1` 的模块看到 `t_{i+k}` 处是什么。这在结构上与自回归解码器消耗自己输出完全相同——使 MTP 模块可直接用作推测解码草稿。

在推理时：将 `h_i^(k-1)` 和起草的 `t_{i+k}` 送入模块 `k+1`，得到 `t_{i+k+1}` 的预测。重复。这正是 EAGLE 风格的草稿，使用训练的 MTP 模块作为草稿网络。DeepSeek-V3 报告第一个 MTP 模块接受率超过80%，加速比约1.8倍。

### 参数核算

对于具有隐藏 `h` 和词汇 `V` 的模型：

- 主模型：数十亿参数，加上一个大小为 `V * h` 的输出头。
- 共享输出头：重用主模型的头。无额外参数。
- 共享嵌入：重用主模型的嵌入。无额外参数。
- 每 MTP 模块：
  - 投影 `M_k`：`(2h) * h = 2h^2`。
  - Transformer 块 `T_k`：注意力（MHA 为 `4h^2`）加上 MLP（SwiGLU 典型为 `8h^2`，比例为8/3）。每块约 `12h^2`。

每模块额外总计：`~14h^2`。对于 DeepSeek-V3 的 `h = 7168`，D = 1 个模块：纸上约 `~14 * 7168^2 = ~720M` 参数。DeepSeek-V3 报告140亿——差异主要是专家层在 MTP 模块中也是 MoE。

### 推测解码回报

在预训练期间，MTP 模块使训练减慢约10%（更多前向计算，额外损失）。回报是双重的：

1. 更密集的训练信号。每个隐藏状态看到 D+1 个监督目标。对 MMLU、GSM8K、MATH、HumanEval 的测量效果：DeepSeek-V3 的消融中一致的几个百分点提升。

2. 推理时免费的推测解码草稿。MTP 模块已经训练预测接下来的几个 Token。重新用作草稿网络，它提供80%+接受率。在该水平，N=3 或 N=5 推测解码给出1.8倍吞吐量。10%的训练时间成本在第一次推理运行时回本。

### 与 EAGLE 的关系

EAGLE 在预训练后单独训练小型草稿模型。MTP 将草稿烘焙到预训练中。两种方法在接受率上收敛，但通过不同的流水线：

| 维度 | EAGLE-3 | MTP (DeepSeek-V3) |
|------|---------|------------------|
| 何时训练 | 预训练后 | 预训练期间 |
| 与现有权重向后兼容 | 是 | 否（需要重新训练） |
| 草稿参数 | 1-2 个 Transformer 层 | 1 个 Transformer 块 + 投影 |
| 接受率 | 0.88-0.92 | 深度1时 0.80+ |
| 超越加速的收益 | 仅推测解码 | 更密集的训练信号 + 加速 |

## 动手实践

`code/main.py` 端到端构建单个 MTP 模块：共享嵌入、投影、Transformer 块、共享输出头。然后计算短合成序列上的每深度交叉熵损失并打印按组件的参数计数。32个 Token 的玩具词汇使数字可读。

### 步骤1：共享嵌入表

主模型 AND 每个深度上的每个 MTP 模块使用的单个 `vocab_size x hidden` 表。不是第二个副本——实际上是相同的张量。

### 步骤2：每深度组合

```python
def combine(prev_hidden, next_token_embed, M_k):
    # 沿特征维度连接，然后投影回隐藏大小
    concat = rms_norm(prev_hidden) + rms_norm(next_token_embed)  # 向量加法替代
    projected = matvec(M_k, concat)
    return projected
```

真实的 DeepSeek-V3 将两个 RMSNormed 向量连接到 `[2h]` 并用 `h x 2h` 矩阵投影。玩具使用向量加法以简洁使用 stdlib。

### 步骤3：深度 k 的 Transformer 块

自注意力加 MLP。在玩具中，单层线性注意力块和 SwiGLU MLP 保持结构可见而不使用 numpy。

### 步骤4：共享输出头

重用主模型的输出投影。词汇上的 Logits。

### 步骤5：每深度损失

Softmax(logits) 与偏移 `k` 处真实 Token 的交叉熵。用 `lambda / D` 缩放因子跨深度聚合。

### 步骤6：参数核算

打印总参数计数、共享（嵌入、头）计数和每模块额外计数。显示 MTP 额外与主模型大小的比率。

## 实际应用

MTP 集成到 DeepSeek-V3（2024年12月）和 DeepSeek-R1 系列中。推理时：

- DeepSeek 自己的服务堆栈开箱即用 MTP 模块作为推测解码器。
- 截至2026年4月，vLLM 和 SGLang 有 DeepSeek-V3 MTP 的集成路径。
- AMD 的 ROCm SGLang 教程显示特定的 MTP 推测解码配置，在 V3 检查点上实测加速1.8倍。

何时在新预训练运行中使用 MTP：

- 你控制完整的预训练流水线并希望存入更密集的训练信号。
- 你知道你将在规模上服务模型并希望免费获得推测解码。
- 你的隐藏大小至少为4096。在10亿规模上，开销伤害大于收益帮助。

何时不使用：

- 对现有预训练稠密模型进行微调。MTP 模块未训练。
- 你想要干净基线进行比较的研究模型。MTP 改变架构。

## 练习题

1. 运行 `code/main.py`。显示每深度损失随合成信号增强而单调下降。修改合成数据使用固定模式并验证深度1和深度2损失都收敛。

2. 计算稠密700亿模型（隐藏8192，80层）D=1 MTP 模块的参数开销。与 DeepSeek-V3 报告的140亿开销比较。解释为什么 DeepSeek 的数字更高：MTP Transformer 块继承相同的 MoE 结构，膨胀每模块参数计数。

3. 在玩具中实现 D=2：添加第二个 MTP 模块，接收 h^(1) 并预测 `t_{i+2}`。验证联合损失和参数核算匹配 DeepSeek 论文的方程19-21。

4. 将玩具切换为并行 MTP（Gloeckle 风格）：在主隐藏状态之上添加 D 个输出头，每个预测不同的偏移。在相同合成信号上测量每深度损失如何与顺序版本比较。对于 k > 1，顺序版本应该产生更低的深度-k 损失，因为它条件于中间预测。

5. 使用训练的 MTP 模块作为 EAGLE 风格草稿：在推理时调用模块 k 提议 `t_{i+k}`。在 held-out 序列上测量这些草稿 Token 对主模型预测的接受率。如果你在玩具上达到50%+，你就重现了 MTP 作为草稿的实证特性。

## 关键术语

| 术语 | 人们怎么说 | 实际含义 |
|------|-----------|---------|
| MTP 模块 | "额外损失块" | 预测主模型前方 `k` 个位置 Token 的小型 Transformer 块加投影 |
| 预测深度 | "哪个偏移" | 整数 `k`，模块 `k` 从前缀到位置 `i` 预测 `t_{i+k}` |
| 并行 MTP | "Gloeckle 风格" | D 个独立头在相同主干隐藏状态上，无条件链 |
| 顺序 MTP | "DeepSeek-V3 风格" | 每个模块条件于前深度的隐藏状态加上下一 Token 的嵌入；保持因果链 |
| 共享输出头 | "重用主头" | MTP 模块调用主模型的 LM 头，不是单独的输出投影 |
| 共享嵌入 | "重用主表" | 到处使用相同的词汇嵌入表；无重复参数 |
| 投影矩阵 M_k | "组合隐藏 + 下一 Token" | 将前隐藏状态和目标 Token 嵌入折叠到下一深度输入的 `h x 2h` 线性层 |
| 联合损失 L_MTP | "平均额外损失" | 每深度交叉熵损失的算术平均，按 `lambda` 缩放 |
| 深度1接受率 | "MTP 草稿多经常正确" | D=1 MTP 模块的 top-1 预测等于主模型 top-1 预测的比率；DeepSeek-V3 上 80%+ |
| Lambda 加权 | "额外损失重要性" | 每深度缩放因子；DeepSeek-V3 上训练开始时0.3，后来0.1 |
