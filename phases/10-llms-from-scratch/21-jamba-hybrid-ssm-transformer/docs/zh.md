# Jamba — 混合 SSM-Transformer

> 状态空间模型（SSM）和 Transformer 想要不同的东西。Transformer 通过二次成本的注意力购买质量。SSM 通过递推购买线性时间推理和恒定内存但滞后质量。AI21 的 Jamba（2024年3月）和 Jamba 1.5（2024年8月）将它们放入同一模型：每7个 Mamba 层1个 Transformer 层，每隔一个块 MoE，以及适合单个80GB GPU 的256k 上下文窗口。Mamba-3（ICLR 2026）用复数值状态空间和 MIMO 投影收紧 SSM 端。本课程从头到尾阅读两种架构并解释为什么当纯 SSM 和纯 Transformer 长上下文尝试失败时，混合方案在三年扩展中幸存下来。

**类型:** 学习
**语言:** Python (stdlib, 层混合计算器)
**前置要求:** 第10阶段·14（开源模型架构），第10阶段·17（原生稀疏注意力）
**时间:** ~60分钟

## 学习目标

- 解释 Jamba 块中的三个原语——Transformer 层、Mamba 层、MoE——以及1:7:偶数交错配方。
- 陈述 SSM 递推在高层的样子以及为什么它实现恒定内存推理。
- 计算256k 上下文中 Jamba 模型的 KV 缓存占用并与纯 Transformer 模型需要的比较。
- 命名三个 Mamba-3 创新（指数梯形离散化、复数值状态更新、MIMO）以及每个针对的问题。

## 问题背景

注意力在序列长度上是二次的。状态空间模型是线性的。这种差异复合：在25.6万 Token 时，Transformer 注意力图每头是650亿条目；SSM 的递推状态无论序列长度如何都是固定大小。

纯 SSM 模型（Mamba、Mamba-2）在小规模上匹配 Transformer 困惑度，但在状态跟踪任务上滞后并在某些类别的上下文内检索上失败。直觉：SSM 将历史压缩成固定状态，当历史很长时信息泄漏。注意力精确记住一切但支付二次成本。

明显的修复：两者都用。在精确回忆重要的地方放 Transformer 层。在其他地方使用 SSM 层。调整比率。Jamba 是第一个在生产级规模（总计520亿，激活120亿，256k 上下文，单个80GB GPU）交付这种混合方案的模型。Jamba 1.5 将家族扩展到总计3980亿/激活940亿。Mamba-3（ICLR 2026）是当前最佳纯 SSM 基线，混合可以围绕其重建。

本课程阅读所有三篇论文并产生"选择正确比率"的心智模型。

## 概念讲解

### 一页中的 SSM

状态空间模型通过固定大小状态 `h` 处理序列 `x_1, ..., x_N`：

```
h_t = A h_{t-1} + B x_t
y_t = C h_t
```

每一步状态通过线性动态 `A` 演变，接受输入 `B x_t`，发出输出 `C h_t`。`A, B, C` 可以学习。注意关键特性：计算 `y_t` 只需要 `h_{t-1}` 和 `x_t`，不需要任何更早的 `x`。内存恒定。推理 O(1) 每 Token。

建模质量的技巧是 `A` 的结构。S4（Gu 2021）使用高度结构化的矩阵，可以在训练期间作为长卷积高效评估。Mamba（Gu, Dao 2023）用数据相关的（"选择性"部分）替换固定的 `A, B, C`。Mamba-2（2024）进一步简化结构。Mamba-3（2026）在特定地方重新添加复杂性。

关键特性：对于解码器 LLM，SSM 层是注意力层的直接替代品，具有固定大小的每层状态而非增长的 KV 缓存。

### Jamba 块

Jamba 块根据两个数字交错层：

- `l`：注意力与 Mamba 比率。Jamba 使用 `l = 8`，意味着每7个 Mamba 层1个 Transformer 层（7个 Mamba + 1个注意力 = 每组8层）。
- `e`：MoE 频率。Jamba 使用 `e = 2`，意味着每隔一层应用 MoE。

块内的层序列：

```
M  M  M  M  M  M  M  A    （7个 Mamba + 1个注意力）
|  M  |  M  |  M  |  M    （其中 | 标记应用 MoE）
```

每个 Jamba 块是8层。在4个块深（32层总计），你得到28个 Mamba 和4个注意力层。其中16个使用 MoE。

### 为什么是1:7比率

AI21 运行消融：多少注意力与 Mamba 比率在参数上给出最佳困惑度 AND 在他们的长上下文评估上的上下文内召回？

- 太多注意力（1:1）：质量上升但内存和速度下降。
- 太少注意力（1:15）：内存很好但上下文内检索失败。
- 最佳点：1:7 或 1:8。

直觉：Transformer 层处理精确召回和状态跟踪。Mamba 层处理便宜的批量处理。

### 位置编码

Mamba 层本身是位置感知的（通过递推）。原始基于 Mamba 的混合中的注意力层不使用 RoPE——SSM 层提供位置信息。Jamba 1.5 为更长上下文泛化在注意力层上添加 RoPE，基于经验长上下文评估的后验改进。

### 内存预算

对于 Jamba-1 形状（32层：28个 Mamba + 4个注意力，隐藏4096，32个注意力头）：

- KV 缓存（仅注意力层）：`2 * 4 * 32 * 128 * 256k * 2 = 8.4 GB` 在256k BF16。只有4个注意力层贡献。
- SSM 状态：`28 * hidden * state_size` 每 Token 前缀，但这是每层固定大小，不随序列长度缩放。典型 Mamba 状态是每特征16，隐藏4096：`28 * 4096 * 16 * 2 = 3.7 MB` 总计。

与32层、相同隐藏、完整32头 MHA 的纯 Transformer 比较：`2 * 32 * 32 * 128 * 256k * 2 = 128 GB` 在256k BF16。KV 缓存8倍减少。即使对抗大多数2024模型使用的 GQA(8) 基线（`2 * 32 * 8 * 128 * 256k * 2 = 32 GB`），Jamba 的1:7混合在16 GB 仍然小2倍。

这就是 AI21 所说的"单个80GB GPU 上256k 上下文"。纯 Transformer 的 KV 缓存装不下；即使是 GQA 基线也没有权重和激活的空间；Jamba 的有。

### Mamba-3：2026年纯 SSM 基线

Mamba-3（ICLR 2026，arXiv:2603.15569）在纯 SSM 端引入三个创新：

1. **指数梯形离散化。** 将 Mamba-2 中的欧拉方法离散化替换为更具表达性的递推。在核心递推内对状态输入应用卷积类操作，而非作为 `x_t` 的外卷积。

2. **复数值状态更新。** 之前的 Mambas 将状态矩阵从复数（S4）减少到实对角（Mamba）到缩放单位（Mamba-2）。Mamba-3 重新添加复数——等效于状态上的数据相关旋转嵌入。这恢复了先前实值简化成本的状态跟踪能力。

3. **多输入多输出（MIMO）投影。** 使用矩阵值投影代替每特征标量投影。改善建模能力并在不增加解码延迟的情况下提高推理时硬件利用率。

在15亿参数时，Mamba-3 在 Gated DeltaNet 上平均下游准确性提高0.6分；MIMO 变体再增加1.2分，总计1.8分增益。在相同状态大小下，Mamba-3 以一半状态匹配 Mamba-2。

Mamba-3 尚未大规模投入生产混合——但在15亿的研究预览中，它是下一个 Jamba 级模型 SSM 端的明显候选。

### 何时使用混合

混合在以下情况获胜：

- 上下文足够长以至于纯 Transformer KV 缓存变得痛苦（64k+）。
- 任务混合短程结构（适合 SSM）与长程召回（需要 Transformer）。
- 你想在单 GPU 内存预算上部署，Transformer KV 缓存单独装不下。

混合在以下情况失败：

- 上下文短（小于16k）。SSM 开销浪费；纯 Transformer 就可以。
- 任务需要处处到处的注意力（深度推理、多文档交叉引用）。混合中注意力层的稀疏性伤害。
- 你正在扩展到万亿参数前沿模型。纯 Transformer + MLA + MoE（DeepSeek-V3 风格）目前正在赢得能力竞赛。

### 竞争格局

| 模型 | 家族 | 规模 | 独特声明 |
|------|------|------|---------|
| Mamba-2 | 纯 SSM | 3B | 线性时间，恒定内存 |
| Jamba | 混合 | 52B/12B | 80GB 上256k |
| Jamba 1.5 Large | 混合 | 398B/94B | 企业级长上下文 |
| Mamba-3 | 纯 SSM | 1.5B（论文） | 状态跟踪恢复 |
| DeepSeek-V3 | 纯 Transformer + MoE | 671B/37B | 前沿能力 |

2026年格局：纯 Transformer MoE 主导前沿，但混合拥有256k+ 上下文利基。Mamba-3 的状态跟踪胜利可能推动下一代混合比率更低（更多 SSM，更少注意力）。

## 实际应用

`code/main.py` 是混合架构的内存计算器。给定 SSM-Transformer 比率和隐藏大小/层数配置，它计算：

- 目标上下文的 KV 缓存。
- SSM 状态内存。
- 上下文 N 的总内存，范围广泛的模型形状。

计算器支持：

- 纯 Transformer 基线（KV 缓存随 N 增长）。
- Jamba 风格1:7混合。
- 纯 SSM（根本没有 KV 缓存）。

数字直接来自 Jamba-1 和 Jamba-1.5 论文的已发布形状和假设变体的外推。

真实部署的集成考虑：

- 大多数生产推理服务器（vLLM、SGLang）支持 Jamba 和 Mamba。检查特定版本。
- 在256k 上下文时，Jamba 的内存优势出现在并发请求吞吐量中。在相同的 VRAM 上你比 Transformer 序列装下更多 Jamba 序列。
- Mamba-3 作为独立模型尚未投入生产——15亿的研究预览。

## 关键术语

| 术语 | 人们怎么说 | 实际含义 |
|------|-----------|---------|
| 状态空间模型（SSM） | "具有固定状态的递推" | 具有学习递推 `h_t = A h_{t-1} + B x_t` 的层；每 Token 恒定内存 |
| 选择性 SSM | "Mamba 的技巧" | 数据相关的 A、B、C 参数，给模型类门控选择性以线性时间 |
| 注意力与 Mamba 比率 | "多少注意力层" | 在 Jamba 中，`l = 8` 意味着每7个 Mamba 层1个注意力层 |
| Jamba 块 | "8层组" | 一个注意力 + 七个 Mamba + 交替位置 MoE |
| SSM 状态 | "隐藏缓冲区" | 替换 Mamba 层 KV 缓存的每层固定大小状态 |
| 256k 上下文 | "Jamba 的旗舰数字" | Jamba-1 适合单个80GB GPU 的序列长度；纯 Transformer 在该大小不能 |
| Mamba-3 | "2026年纯 SSM" | 当前最佳纯 SSM 架构，具有复数状态 + MIMO；混合围绕重建的基线 |
| MIMO | "多输入多输出" | 使用矩阵值投影代替每特征标量的 Mamba-3 创新 |
| 指数梯形离散化 | "Mamba-3 的递推" | 子包 Mamba-2 欧拉方法离散化的更具表达性的递推 |
| 混合架构 | "混合注意力和 SSM" | 任何交错 Transformer 和 SSM 层的模型；Jamba 是生产原型 |
