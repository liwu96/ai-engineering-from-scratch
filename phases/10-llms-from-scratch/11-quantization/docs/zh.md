# 量化：让模型适配

> 70B 模型在 FP16 中需要 140GB。两块 A100 仅用于权重。量化为 FP8：一块 80GB GPU。INT4：一台 MacBook。

**类型:** 构建
**语言:** Python (使用 numpy)
**前置要求:** 第10阶段，第01-10课（从头开始的 LLM）
**时间:** ~120分钟

## 学习目标

- 实现从 FP16 到 INT8 和 INT4 的对称和非对称量化，包括每张量和每通道缩放
- 计算量化带来的内存节省，并确定哪种精度适合给定 GPU 的 VRAM
- 解释训练后量化（PTQ）和量化感知训练（QAT）的区别
- 应用 GPTQ 或 AWQ 量化真实模型，并在基准上测量准确性-内存权衡

## 问题背景

Llama 3 70B 有 700 亿参数。每个参数是一个 16 位浮点数。那是 1400 亿字节。140GB。一块 A100 有 80GB VRAM。你甚至无法加载权重，更不用说运行推理了。你需要两块每小时 $2 的 A100 仅服务一个模型。

但每个参数 16 位是浪费的。神经网络中的大多数权重聚集在零附近。如果你测量 Llama 3 70B 中权重的实际分布，95% 落在 -0.1 和 +0.1 之间。你正在燃烧 16 位来表示可以用 4 位容纳的值。

量化用低精度数字替换高精度数字。FP16 到 FP8 内存减半。FP16 到 INT4 减到四分之一。那个 140GB 模型变成 35GB。它适配在单块消费级 GPU 上。推到 2 位量化（激进、有损，但对某些任务可用），同一模型在 16GB 笔记本上运行。

代价是准确性。你移除的每个位都破坏信息。问题是你损失多少准确性，在哪里损失。精心量化的 INT4 模型在大多数基准上保留原始模型 95-99% 的质量。朴素的 INT4 量化可以完全摧毁模型。区别在于技术。

社区使用 GPTQ 将 Llama 3 量化到 INT4，在 WikiText 上显示大约 1-2 个困惑度点的损失。Mistral 发布了 Mixtral 8x22B 的 FP8 检查点，在 MMLU 上零可测量质量损失。GGUF 格式驱动 llama.cpp，在配备 M 系列芯片的 MacBook 上运行 70B 模型。量化不是黑客。它是每个大于 7B 的模型的标准部署路径。

## 概念讲解

### 数字格式：每位做什么

每个浮点数有三个部分：符号、指数和尾数（也称为有效数字）。符号是 1 位。指数决定范围（数字可以多大或多小）。尾数决定精度（你得到多少位小数）。

```
FP32:  [1 符号] [8 指数] [23 尾数]  = 32 位
FP16:  [1 符号] [5 指数] [10 尾数]  = 16 位
BF16:  [1 符号] [8 指数] [7  尾数]  = 16 位
FP8:   [1 符号] [4 指数] [3  尾数]  = 8  位 (E4M3)
FP8:   [1 符号] [5 指数] [2  尾数]  = 8  位 (E5M2)
INT8:  [1 符号] [7 数值]             = 8  位 (均匀步长)
INT4:  [1 符号] [3 数值]             = 4  位 (总共 16 级)
```

**FP32** 是完整精度。23 位尾数给出约 7 位十进制精度。范围：大约 1.2 x 10^-38 到 3.4 x 10^38。训练过去完全在 FP32 中进行。对于累加（矩阵乘法期间的运行和）仍然如此。

**FP16** 将位数减半。10 位尾数给出约 3.3 位十进制数字。指数缩小到 5 位，大幅缩小范围（最大值 ~65,504）。这对权重（聚集在零附近）没问题，但对激活和梯度危险，它们可能在训练期间飙升。FP16 训练需要损失缩放以防止下溢。

**BF16**（Brain Float 16）保持 FP32 的 8 位指数，但将尾数缩小到 7 位。与 FP32 相同的范围，比 FP16 更少的精度。Google 专门为深度学习设计它。直觉：范围比神经网络精度更重要。在 FP16 中下溢到零的 10^-20 梯度在 BF16 中存活。在 BF16 中从 0.07342 舍入到 0.0734 的权重足够接近。每个现代训练运行都使用 BF16 或 BF16/FP32 混合。

**FP8** 有两种变体。E4M3（4 位指数，3 位尾数）用于推理期间的权重和激活。E5M2（5 位指数，2 位尾数）用于训练期间的梯度，其中范围比精度更重要。H100 GPU 上的 FP8 推理比 FP16 快 30-50%，质量损失可以忽略。

**INT8** 是整数格式。没有指数，没有尾数。只有 256 个均匀间隔的值，从 -128 到 127。你需要一个缩放因子将浮点权重映射到这个范围。优势：整数运算比浮点更快、更省电。A100 上的 INT8 矩阵乘法以 624 TOPS 运行，而 FP16 为 312 TFLOPS。

**INT4** 进一步推进。只有 16 个可能值。缩放因子承担重任。质量完全取决于如何选择缩放以及量化哪些权重。最先进的 INT4 方法（GPTQ、AWQ）保留原始模型 95%+ 的质量。

### 量化如何工作

核心操作很简单。取一个浮点值张量，找到一个缩放因子，相乘，舍入到最近整数，并存储整数加缩放因子。

**量化：**
```
scale = max(abs(tensor)) / max_int_value
quantized = round(tensor / scale)
```

**反量化：**
```
reconstructed = quantized * scale
```

对于对称范围为 INT8（-127 到 127）：
```
scale = max(abs(tensor)) / 127
quantized = clamp(round(tensor / scale), -128, 127)
```

误差是舍入误差。每个值最多可以偏差 `scale / 2`。跨层的总误差取决于你有多少权重以及模型对这些权重扰动的敏感程度。

**每张量 vs 每通道量化。** 每张量对整个权重矩阵使用一个缩放因子。简单但有损：如果一列有大值而另一列有小值，小值失去大部分精度。每通道对每个输出通道（权重矩阵的每行或每列）使用一个缩放因子。更多开销（你存储 N 个缩放因子而不是 1 个）但质量大幅提升。每个生产量化方法都使用每通道或更细的粒度。

**非对称量化**添加零点偏移：`quantized = round(tensor / scale) + zero_point`。这处理不以零为中心的分布。例如，ReLU 激活总是非负。对称量化将浪费一半的整数范围在从未出现的负值上。非对称量化将实际范围 [min, max] 映射到完整整数范围。

### 敏感度层次

模型中不是所有东西对量化的容忍度都相同。有一个清晰的层次。

**权重（最鲁棒）。** 模型权重在训练期间变化缓慢，遵循大致以零为中心的高斯分布。它们量化得很好。每通道缩放的 INT8 权重产生几乎无损的结果。INT4 需要更复杂的方法，但可行。

**激活（中等敏感度）。** 激活是推理期间流经网络的中间值。它们的动态范围比权重宽，包含异常值。单个注意力头可能产生比均值大 100 倍的激活值。这些异常值对模型质量至关重要。朴素量化破坏信息。解决方案：将异常值通道保持在高精度（LLM.int8()），使用每 Token 或每通道激活缩放。

**KV 缓存（高敏感度）。** 键值缓存存储所有先前 Token 的注意力状态。在长上下文长度下，KV 缓存主导内存。对于 32K 上下文中的 70B 模型，仅 KV 缓存就是 FP16 中的 40GB。将 KV 缓存量化到 FP8 或 INT8 节省大量内存，但任何错误都会在未来所有注意力计算中累积。质量影响随序列长度缩放。

**注意力 logits（最敏感）。** 注意力中的 softmax 对其输入的微小变化高度敏感。softmax 前对数中的 0.01 量化误差可以有意义地转移注意力分布。即使其他一切都已量化，大多数量化方案也将注意力计算保持在高精度（FP16 或 BF16）。

### PTQ vs QAT

**训练后量化（PTQ）**量化已经训练好的模型。没有重新训练。你取 FP16 权重，计算缩放因子，舍入，部署。快速（分钟到小时）且便宜。对 INT8 和 FP8 效果很好。对于 INT4，朴素 PTQ 经常失败，因为舍入误差累积。高级 PTQ 方法（GPTQ、AWQ）使用校准数据来最小化量化误差。

**量化感知训练（QAT）**在前向传递中插入假量化操作到训练期间。模型学习将权重放在舍入误差小的位置。梯度使用直通估计器（STE）流过假量化：假装舍入操作的梯度为 1。QAT 比 PTQ 产生更好的 INT4 和 INT2 模型，但需要完整的训练运行。Google 对 Gemini 的高效服务使用 QAT。Meta 对某些 Llama 部署目标使用 QAT。

| 方面 | PTQ | QAT |
|------|-----|-----|
| 成本 | 分钟到小时 | 完整训练运行 |
| INT8 质量 | 优秀（< 0.1% 损失） | 优秀 |
| INT4 质量 | GPTQ/AWQ 良好（1-3% 损失） | 更好（< 1% 损失） |
| INT2 质量 | 差 | 对某些任务可用 |
| 校准数据 | 128-1024 个示例 | 完整训练数据集 |
| 何时使用 | 部署、迭代 | 最大质量低比特宽 |

### GPTQ、AWQ、GGUF

**GPTQ（GPT 量化）**是一种一次性 PTQ 方法。它一次量化一层，使用小校准数据集（128 个示例是典型的）来测量 Hessian（关于每个权重输出敏感度的二阶信息）。Hessian 说重要的权重被更仔细地量化。GPTQ 是第一个使 LLM 的 INT4 量化实用的方法。TheBloke 在 Hugging Face 上通过发布数百个模型的量化版本推广了 GPTQ。

**AWQ（激活感知权重量化）**观察到一小部分权重（约 1%）因为与大激活值相乘而异常重要。AWQ 使用校准数据识别这些显著权重，并在量化前放大它们（然后相应缩小激活）。这保持重要权重的范围在 INT4 量化准确的位置。AWQ 通常匹配或略优于 GPTQ 质量，同时应用速度快 1.5-2 倍。

**GGUF（GPT 生成的统一格式）**是 llama.cpp 及其生态系统使用的文件格式。它支持混合量化：不同层获得不同比特宽。第一层和最后一层（嵌入和输出头）通常保持更高精度。中间层获得 INT4 或 INT3。GGUF 文件是自包含的：权重、分词器、元数据都在一个文件中。该格式为 CPU 推理和 Apple Silicon 设计，将整个模型加载到内存并在 CPU 或 Metal GPU 上运行矩阵乘法是标准路径。Q4_K_M 是最流行的 GGUF 量化变体，平衡质量和大小。

### 质量测量

你如何知道量化模型仍然良好？

**困惑度。** 最常见的指标。越低越好。在留出数据集（WikiText-2 是标准）上为原始模型和量化模型计算困惑度。增量告诉你量化破坏了多少信息。经验法则：增量 < 0.5 优秀，0.5-1.0 良好，1.0-2.0 对大多数任务可接受，> 2.0 意味着出了问题。

**任务特定基准。** 在 MMLU、HumanEval、GSM8K 或你的自定义评估套件上运行量化模型。与原始模型比较。量化不均匀影响不同能力。数学和代码任务比通用知识对精度损失更敏感。

**输出生成比较。** 从两个模型在相同提示上生成响应并比较。LLM 作为评判者（第10课）在这里表现良好。计算胜率：量化模型与原始模型匹配或更好的提示比例？

**延迟和吞吐量。** 量化存在是为了让模型更快、更便宜。测量每秒 Token 数、首个 Token 时间和内存使用。比原始模型慢的量化模型比无用更糟。

| 模型 | 格式 | 大小 | 困惑度 (WikiText-2) | MMLU | 每秒 Token 数 (A100) |
|-------|--------|------|---------------------|------|---------------------|
| Llama 3 70B | FP16 | 140GB | 3.12 | 79.5% | 38 |
| Llama 3 70B | FP8 | 70GB | 3.14 | 79.3% | 55 |
| Llama 3 70B | GPTQ INT4 | 35GB | 4.32 | 77.8% | 72 |
| Llama 3 70B | AWQ INT4 | 35GB | 4.18 | 78.1% | 75 |
| Llama 3 70B | GGUF Q4_K_M | 40GB | 4.25 | 77.9% | 28 (CPU) |

模式：FP8 几乎免费。INT4 花费 1-2 个 MMLU 点，但将吞吐量翻倍并将内存减至四分之一。对几乎每个部署来说，这个权衡都是值得的。

### 真实数字

H100 上 FP16 到 FP8：30-50% 推理加速，< 0.1% 质量损失。这是显而易见的量化。每个 H100 部署都应该使用它。

FP16 到 INT8（LLM.int8()）：内存减半，< 0.5% 质量损失。混合精度方法将异常特征保持在 FP16，同时将所有其他量化到 INT8。

FP16 到 INT4（GPTQ/AWQ）：内存减至四分之一，取决于模型和方法 1-3% 质量损失。在单块 48GB GPU 上启用 70B 模型。

FP16 到 INT4（GGUF Q4_K_M）：内存减至 3.5 倍，1-2% 质量损失。针对 CPU 推理优化。M3 Max 64GB 上 Q4_K_M 的 70B 模型约 40GB，以 10-15 Token/秒运行。

FP16 到 INT2：内存减至八分之一，5-15% 质量损失。仅在你能容忍退化的特定狭窄任务上可行。研究前沿，尚未准备好用于通用生产。

## 动手实践

### 步骤1：数字格式表示

构建每种格式的位级表示，以查看符号、指数和尾数到底做什么。

### 步骤2：对称量化（每张量和每通道）

基本量化操作。每张量对整个矩阵使用一个缩放。每通道对每行或每列使用一个缩放。

### 步骤3：质量测量

测量量化破坏了多少信息。均方误差、信噪比和原始与重建张量之间的余弦相似度。

### 步骤4：比特宽度扫描

在同一数据上将相同张量量化为不同比特宽度（2、3、4、8、16）并测量每个级别的质量。这显示质量悬崖到底在哪里。

### 步骤5：敏感度实验

模拟量化 Transformer 的不同部分并测量哪些组件最敏感。这演示敏感度层次：权重 < 激活 < KV 缓存 < 注意力。

### 步骤6：模拟 GPTQ

GPTQ 一次量化一列，使用 Hessian 决定如何分配舍入误差。这是一个捕获核心思想的简化版本：使用校准数据测量权重重要性，然后更激进地量化最不重要的权重。

### 步骤7：AWQ 模拟

AWQ 识别显著权重（那些与大激活相乘的）并通过缩放在量化前保护它们。

### 步骤8：完整管道

将所有内容连接起来。在同一权重矩阵上比较朴素量化、每通道、GPTQ 和 AWQ。

## 练习题

1. 实现组量化。不是每通道一个缩放，而是在通道内每组 128 个权重使用一个缩放。这就是 GPTQ 和 AWQ 实际使用的。在同一权重矩阵上比较 32、64、128 和 256 的组大小。更小组给出更好的质量，但缩放因子的存储开销更大。

2. 构建混合精度量化器。在网络的多层中将第一层和最后一层量化为 INT8，中间层量化为 INT4。与统一 INT4 和统一 INT8 比较端到端输出质量。测量与全 INT8 相比的内存节省。

3. 实现量化感知训练的直通估计器（STE）。在简单两层网络的回归任务训练中，在前向传递插入假量化/反量化操作。比较正常训练（然后 PTQ 到 INT4）与从头开始 QAT 训练的最终损失。

4. 构建受 LLM.int8() 启发的异常值感知量化器。检测激活幅度超过均值 6 倍的通道。将这些通道保持在 FP16，其他所有内容量化到 INT8。在来自步骤5的 Transformer 层上测量不同异常值阈值（3 倍、6 倍、10 倍）的端到端质量。

5. 实现量化质量仪表板。给定权重矩阵，计算并显示：权重分布直方图、量化误差分布、每通道缩放因子、量化最差通道（最高重建误差），以及 100 个随机输入上原始和量化输出之间的余弦相似度。识别应保持更高精度的通道。

## 关键术语

| 术语 | 人们怎么说 | 实际含义 |
|------|-----------|---------|
| FP16 | "半精度" | 16 位浮点，5 位指数和 10 位尾数，最大值 65,504，标准推理格式 |
| BF16 | "Brain 浮点" | 16 位浮点，8 位指数（与 FP32 相同范围）和 7 位尾数，Google 为训练设计 |
| FP8 | "八位浮点" | 两种变体：E4M3（推理，更多精度）和 E5M2（训练，更多范围），H100 原生支持 |
| INT8 | "八位整数" | 256 个均匀间隔的值，从 -128 到 127，需要缩放因子从浮点映射 |
| INT4 | "四位整数" | 总共 16 级，需要复杂方法（GPTQ、AWQ）来保持质量 |
| 每通道量化 | "每行一个缩放" | 对每个输出通道使用单独的缩放因子，而不是整个张量一个，大幅减少误差 |
| GPTQ | "Hessian 方法" | 使用后验训练量化，使用二阶信息最小化输出误差，一次一层 |
| AWQ | "激活感知" | 在量化前放大显著权重（那些与大激活相乘的）以保护它们 |
| GGUF | "llama.cpp 格式" | 自包含模型文件，混合精度层，针对 CPU 和 Apple Silicon 推理优化 |
| PTQ | "训练后量化" | 将训练模型权重转换为较低精度而无需重新训练，快速但在极端压缩下有限 |
| QAT | "训练中量化" | 在前向传递中插入假量化，使模型学会容忍舍入，在 INT4/INT2 下更好 |
| 校准数据 | "128 个示例" | 通过模型运行以计算激活统计数据来设置缩放因子的小数据集 |
| 缩放因子 | "乘数" | 浮点范围和整数范围之间的转换：`float_val = int_val * scale` |
| 困惑度增量 | "差了多少" | 原始和量化模型之间困惑度的差异，< 0.5 优秀，> 2.0 有问题 |
