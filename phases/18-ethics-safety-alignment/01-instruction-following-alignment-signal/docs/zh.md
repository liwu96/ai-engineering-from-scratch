# 指令遵循作为对齐信号

> 之后对 RLHF 的每个批评都针对这个流程。在你研究优化压力如何扭曲代理之前，你必须看到这个代理。InstructGPT (Ouyang 等人，2022) 定义了参考架构：在指令-响应对上的监督微调、在成对偏好排名上训练的奖励模型，以及针对奖励模型的 PPO 并带有对 SFT 策略的 KL 惩罚。一个 13 亿参数的 InstructGPT 比一个 1750 亿参数的 GPT-3 更受青睐。那个单一结果就是 2026 年每个前沿实验室仍然发布 RLHF 形状后训练流程的原因。

**类型:** 学习
**语言:** Python (标准库，玩具三阶段流程)
**前置要求:** 第 10 阶段 · 第 06 课 (SFT)，第 10 阶段 · 第 07 课 (RLHF)，第 10 阶段 · 第 08 课 (DPO)
**时间:** ~45 分钟

## 学习目标

- 说出 InstructGPT 流程的三个阶段和每个阶段使用的损失。
- 解释为什么一个 13 亿参数的指令微调模型在人类偏好评估上击败了原始的 1750 亿参数 GPT-3。
- 说明第 3 阶段 KL 惩罚在保护什么，以及为什么移除它会坍缩为模态寻找行为。
- 描述对齐税和 Ouyang 等人用来缓解它的 PPO-ptx。

## 问题背景

预训练语言模型补全文本。它们不回答问题。问 GPT-3 "写一个反转列表的 Python 函数"，你通常会得到另一个提示，因为大多数训练分布是继续更多网页文本的网页文本。模型在做它的工作 —— 这个工作是错的。

每个严肃实验室用来修复这个问题的代理是人类偏好。两个补全交给标注员；标注员选择更好的那个；奖励模型学习标注员。然后 RL 循环将策略转向奖励模型打分高的输出。这就是三句话的完整 InstructGPT 论点。论文其余部分是工程。

## 概念讲解

### 第 1 阶段：监督微调 (SFT)

收集提示-响应对，其中响应是善意人类会写的内容。Ouyang 等人使用了来自标注员和 OpenAI API 的 13k 提示。在这个数据上用标准交叉熵损失微调基础模型。

SFT 给你的：模型现在回答问题而不是继续它们。它不给你什么：当多个都合理时，关于标注员更喜欢哪个答案的信号。

### 第 2 阶段：奖励模型 (RM)

对每个提示，从 SFT 模型采样 K 个补全。标注员对它们排名。训练一个奖励模型，对任何提示-响应对打分，使得对于 `y_w` 优于 `y_l` 的对：

```
L_RM = -log sigmoid(r(x, y_w) - r(x, y_l))
```

这是 Bradley-Terry 成对偏好损失。RM 通常从 SFT 模型初始化，LM 头替换为标量头。

奖励模型很小：60 亿参数对 1750 亿参数 InstructGPT 就够了。它们也很脆弱 —— 论文第 5 节主要是关于在小规模上出现的奖励黑客行为。

### 第 3 阶段：带 KL 惩罚的 PPO

定义目标：

```
J(pi) = E_{x~D, y~pi(.|x)} [ r(x, y) ] - beta * KL(pi(.|x) || pi_SFT(.|x))
```

用 PPO 最大化。KL 项阻止 `pi` 远离 SFT 策略。没有它，优化器找到对抗样本 —— 在 RM 下得分高的字符串，因为 RM 从未见过它们，不是因为人类真的更喜欢它们。

KL 系数 `beta` 是单个最重要的 RLHF 超参数。太低：奖励黑客。太高：相比 SFT 没有改进。

### 对齐税

RLHF 后，模型被人类偏好但在标准基准 (SQuAD、HellaSwag、DROP) 上退步。Ouyang 等人称之为对齐税，并用 PPO-ptx 修复：将预训练梯度混合到 RL 目标中，使模型不会忘记如何完成 RLHF 从未奖励的下游任务。

```
J_ptx(pi) = J(pi) + gamma * E_{x~D_pretrain} [ log pi(x) ]
```

PPO-ptx 成为标准。Anthropic、DeepMind 和 Meta 都使用某种变体。

### 结果

一个 13 亿参数 InstructGPT (SFT + RM + PPO-ptx) 在大约 70% 的时间里被标注员优先于 1750 亿参数基础 GPT-3。在生产流量的隐藏测试提示上差距扩大。从这个数字读出两件事：

1. 对齐是与能力不同的维度。1750 亿参数模型有更多能力；13 亿参数模型有更多对齐；标注员更喜欢对齐的那个。
2. 能力下限由基础模型设定。你无法将基础模型 RLHF 成知道它从未见过的事实。

### 为什么这是第 18 阶段的参考点

后续课程的每个批评 —— 奖励黑客 (第 2 课)、DPO (第 3 课)、谄媚 (第 4 课)、CAI (第 5 课)、沉睡智能体 (第 7 课)、对齐伪装 (第 9 课) —— 都针对这个流程的某些部分。奖励黑客攻击第 2 阶段。DPO 折叠第 2 和第 3 阶段。CAI 替换人类标注员。谄媚表明标注员是有偏差的信号。对齐伪装表明策略可以完全绕过第 3 阶段。你脑子里没有这个流程就无法理解这些批评中的任何一个。

## 使用它

`code/main.py` 在玩具偏好数据上模拟三个阶段。基础"策略"是对动作 {A, B, C} 的有偏硬币。第 1 阶段 SFT 模仿 200 个提示上的标注员动作。第 2 阶段从 500 个成对排名拟合 Bradley-Terry 奖励模型。第 3 阶段运行带 KL 惩罚的简化 PPO 更新到 SFT 策略。你可以观察奖励上升、KL 散度增长和策略漂移 —— 你可以关闭 KL 项，看在 50 个更新步骤内奖励黑客如何出现。

要看什么：

- `beta = 0.1` vs `beta = 0.0` 的奖励轨迹。
- 训练步骤上的 KL(pi || pi_SFT)。
- 与标注员偏好相比的最终动作分布。

## 产出成果

本课程产生 `outputs/skill-instructgpt-explainer.md`。给定 RLHF 流程描述或论文摘要，它识别三个阶段中哪个被修改，每个阶段使用什么损失，以及是否存在 KL 惩罚或等效正则化器。

## 练习题

1. 运行 `code/main.py`。设置 `beta = 0.0` 并报告 200 个 PPO 步骤后的动作分布。用一段话解释模态寻找行为。

2. 修改奖励模型对动作 B 有 +0.5 偏差 (模拟奖励错误)。用 `beta = 0.1` 运行 PPO。KL 惩罚阻止策略利用偏差吗？在什么 `beta` 下利用变得可见？

3. 阅读 Ouyang 等人 (arXiv:2203.02155) 图 1。通过运行 PPO 1、5、20、100 步骤并测量对 SFT 模型的偏好，复现标注员偏好曲线。

4. 论文第 4.3 节报告 13 亿参数 InstructGPT 在大约 70% 的时间里击败 1750 亿参数 GPT-3。为什么在隐藏生产提示上比例会比标注员自己的提示更高？

5. 用相同偏好数据将 PPO 损失替换为 DPO (第 10 阶段 · 第 08 课)。比较最终策略漂移 (到 SFT 的 KL) 和最终奖励。哪种方法在匹配奖励时漂移更远？

## 关键术语

| 术语 | 人们怎么说 | 实际含义 |
|------|----------|----------|
| SFT | "指令微调" | 第 1 阶段：在提示-响应对上用交叉熵微调 |
| 奖励模型 | "RM" | 在成对标签上用 Bradley-Terry 训练的 (提示, 响应) 标量回归器 |
| Bradley-Terry | "成对偏好损失" | -log sigmoid(r_w - r_l)；将成对排名归约为二分类 |
| KL 惩罚 | "正则化器" | `beta * KL(pi || pi_SFT)` —— 将 RL 策略保持在 SFT 锚点附近 |
| PPO-ptx | "带预训练混合的 PPO" | 将预训练对数似然的一部分加到 PPO 目标中以抵消对齐税 |
| 对齐税 | "RLHF 回归" | RLHF 后未针对的标准基准下降 |
| 标注员偏好 | "基本事实" | 人类排名样本；RM 是对此的统计代理，不是对"人类价值观"的代理 |
