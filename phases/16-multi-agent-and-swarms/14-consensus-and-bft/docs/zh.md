# 共识与拜占庭容错机制

> 经典分布式系统BFT遇上随机LLM。2025-2026年间三个研究方向涌现：**CP-WBFT**(arXiv:2511.10400)通过置信度探测加权投票；**DecentLLMs**(arXiv:2507.14928)采用无领导架构，工作者并行提案、几何中位数聚合；**WBFT**(arXiv:2505.05103)结合加权投票与分层结构聚类，区分核心节点和边缘节点。"Can AI Agents Agree?"(arXiv:2603.01213)的实证结果是：即使是标量共识也脆弱——单个欺骗性Agent可破坏Mixture-of-Agents。BFT必要但不充分。本lesson构建最小BFT协议，注入三种Agent特有攻击（拜占庭撒谎、讨好式从众、相关错误单一化），测量各共识变体如何应对。

**类型:** 学习+构建
**语言:** Python(stdlib)
**前置要求:** 阶段16课程07(Society of Mind和Debate)、阶段16课程13(Shared Memory)
**时间:** ~75分钟

## 问题背景

你有N个LLM Agent各自产出答案。它们不一致。多数投票选出错误答案，因为两个Agent相关（同基座模型、同训练数据、同失败模式）。第三个Agent恰好以新方式错误——多数是假多数。

再加一个欺骗性Agent：故意撒谎。或讨好型Agent：赞同最后发言者。经典BFT假设拜占庭节点比例`f < n/3`且任意行为。2026现实是：LLM节点即使诚实也随机，跨模型相关，受彼此输出影响。不能当作独立Bernoulli投票者。

经典BFT(PBFT，1999)不错——但不完整。它处理任意位翻转。不处理"三个诚实Agent共享幻觉因为共享训练数据"。本lesson从PBFT基础出发，叠加三层2025-2026适配。

## 概念讲解

### 经典BFT给你什么

实用拜占庭容错(Castro & Liskov，OSDI 1999)容忍`f < n/3`拜占庭节点。协议三阶段(pre-prepare、prepare、commit)，两原语(签名消息、仲裁证书)。`n >= 3f + 1`诚实或恶意节点对单一值达成共识。

保证强但假设：

1. **独立故障。**拜占庭不协调。
2. **诚实节点真正诚实。**诚实输出正确性非问题；协议只对齐分歧。
3. **问题有真实答案。**对错误事实共识仍是共识。

LLM Agent违反全部三点。同基座模型Agent共享故障。"诚实"LLM仍幻觉。模糊问题上"真相"是Agent决定——无外部oracle。

### 三种LLM特有攻击

**拜占庭撒谎。**一个Agent输出故意错误答案。经典BFT若`f < n/3`可处理。

**讨好式从众。**一个Agent读其他答案后投票，对齐最后发言者。非恶意但与最大声相关。经典BFT不阻止，因为Agent通过每项签名检查。

**相关错误单一化。**三个Agent共享基座模型。它们幻觉同错误答案。多数错。经典BFT无助，因为三个"诚实"一致。

### 2025-2026响应

**CP-WBFT**(arXiv:2511.10400)——置信度探测加权BFT。每个投票者附置信度探测（自报告概率，或单独校准模型预测）。投票权重随置信度缩放。报告完全图上+85.71% BFT改进。缓解讨好式从众（从众Agent对志愿立场置信度低）。

**DecentLLMs**(arXiv:2507.14928)——无领导。工作者Agent并行提案，评估者Agent评分提案，最终答案是评分位置几何中位数。`f < n/2`时鲁棒。缓解拜占庭撒谎和相关错误（几何中位数抗离群值，拉向密集簇而非模型偏向均值）。

**WBFT**(arXiv:2505.05103)——带分层结构聚类加权BFT。投票权重由响应质量加历史学习信任分数分配。聚类Agent为核心和边缘；核心Agent先达成共识，边缘跟随。缓解可扩展性（核心共识小且快）和部分单一化（核心可选多样性）。

### 实证："Can AI Agents Agree?"(arXiv:2603.01213)

论文测量标量共识（LLM Agent对单一数值达成一致）跨多个前沿模型。发现令人不安：

- 无对手时，LLM Agent在标量问题上分歧率超30%。
- 单个采用欺骗人设的Agent可将Mixture-of-Agents共识偏离诚实基线40+百分点。
- 分歧率与模型多样性相关——异构ensemble分歧更多（好：错误不相关）但也更慢收敛（坏：更长时间达成共识）。

教训：BFT提供对齐输出机制，但不告诉你对齐输出是否正确。结合验证（阶段16课程08角色专业化）、多样性（阶段16课程15辩论变体）、评估者Agent（阶段16课程24基准）。

### 核心协议，精简版

LLM Agent最小BFT轮：

```
1. 任务到达；每个Agent i产出答案 a_i
2. 每个Agent附置信度探测 c_i in [0, 1]
3. 聚合器从所有n个Agent收集 (a_i, c_i)
4. 聚合器按语义聚类分组（等效答案）
5. 聚合器计算每个簇C权重：
     w(C) = sum_{i in C} c_i
6. winner = 最大权重簇，若 max > threshold * sum(c_i)
   否：重试或升级
7. 少数簇带provenance记录供事后审计
```

语义聚类是LLM特有转折。两答案"研究报告4.2%"和"4.2%改进"是同簇。朴素字符串相等检查会漏此。生产中用便宜嵌入模型或显式规范化。

### 阈值调优

`threshold`参数决定何时接受何时重试。太低：接受弱多数。太高：永不接受。实证范围：`n=5-7` Agent时0.5-0.67，更小n时更高。低于阈值，升级人工或不同Agent ensemble。

### 共识无助之处

- **模糊问题。**若问题无真值，共识是意见。称之为意见。
- **复合问题。**"写代码并解释"——两个答案。各自独立投票。
- **对抗多轮。**若Agent可观察前轮并模仿(Du 2023辩论)，它们开始彼此赞同不管真相。限轮数（典型2-3）。

## 构建

`code/main.py`实现：

- `AgentVoter`——带(答案、置信度)的脚本策略。
- `MajorityVote`——经典 plurality。
- `CPWBFT`——带语义聚类的置信度加权投票。
- `DecentLLMs`——评分提案几何中位数聚合。
- `Scenario`——三种攻击模式下运行各聚合器。

攻击模式实现：

1. `byzantine`：一个Agent高置信撒谎。
2. `sycophancy`：一个Agent复制看到的第一个答案，匹配置信度。
3. `monoculture`：三个Agent共享错误答案（相关错误），中等置信度。

跑：

```
python3 code/main.py
```

预期输出：(攻击、聚合器) → 最终答案表，正确答案高亮。Plurality失败单一化案例。CPWBFT置信度加权缓解讨好。DecentLLMs几何中位数在单一化少于半数人口时拉向诚实簇。

## 交付成果

部署任何共识机制前：

- **攻击测试至少三种模式。**协议应可预测失败，非静默。
- **记录每个少数簇带provenance。**少数簇是相关错误早期预警系统。
- **强制限轮。**无"继续辩论直到一致"——奖励讨好。
- **分离共识与正确性。**共识输出送验证者；验证者独立ensemble。
- **监控共识率。**陡升意味从众偏；陡降意味模型漂移。

## 关键术语

| 术语 | 人们怎么说 | 实际含义 |
|------|------------|----------|
| BFT | "拜占庭容错" | Castro-Liskov 1999协议，容忍`f < n/3`任意故障共识。 |
| Byzantine | "任何坏行为" | 节点可撒谎、丢消息、静默失败——任何事但安全崩溃。 |
| 置信度探测 | "你多确定?" | 自报告或校准器预测概率附投票。 |
| 语义聚类 | "同答案不同词" | 计票前分组等效答案。 |
| 几何中位数 | "鲁棒中心" | 最小化到样本点距离之和的点。抗离群值，不同于均值。 |
| 单一化 | "同模型同失败" | Agent共享训练数据或基座模型时相关错误。 |
| 讨好式从众 | "赞同大声者" | Agent投票偏向最先/最大声发言者。 |
| Core/Edge | "分层BFT" | WBFT划分：小核心先共识，边缘跟随。限延迟。 |
