# FIPA-ACL 与言语行为传承

> 在 MCP 之前，在 A2A 之前，有 FIPA-ACL。2000 年，IEEE 智能物理代理基金会通过了一种代理通信语言，包含二十种施事行为、两种内容语言和一组交互协议——合同网、订阅/通知、请求-条件。它因本体论开销对 Web 来说太重而逐渐淡出业界，但多智能体系统的 LLM 复兴正在悄悄地用更宽松的语义重新实现相同的理念：JSON 契约代替施事行为，自然语言代替本体论。本课程认真研读 FIPA-ACL，让你看清哪些 2026 年的协议决策是重新发明，哪些是真正创新，以及当前浪潮将在何处重新发现 2000 年代已经解决的问题。

**类型:** 学习
**语言:** Python (标准库)
**前置要求:** 第 16 阶段 · 第 01 课 (为什么需要多智能体)
**时间:** ~60 分钟

## 问题背景

2026 年代理协议格局繁忙：MCP 用于工具，A2A 用于智能体，ACP 用于企业审计，ANP 用于去中心化信任，NLIP 用于自然语言内容，还有 CA-MCP 和二十多个研究提案。每个规范都声称自己是基础性的。

诚实的看法是，它们大多数都在重新发现一个特定的二十年前的决策树。Austin (1962) 和 Searle (1969) 的言语行为理论给了我们"话语即行动"。KQML (1993) 将其变成了有线协议。FIPA-ACL (2000 年通过) 产生了参考标准化：二十种施事行为、内容语言 SL0/SL1、合同网和订阅-通知的交互协议。JADE 和 JACK 是 Java 参考平台。这项工作在 2010 年左右逐渐消退，因为本体论开销太重，而 Web 正在获胜。

当你看到 MCP 的 `tools/call`、A2A 的任务生命周期或 CA-MCP 的共享上下文存储时，你看到的是 FIPA 决策的一种更软、JSON 原生的重述。了解传承告诉你两件事：哪些新"创新"实际上是重新发明，以及新规范将重新发现哪些旧的失败模式。

## 概念讲解

### 言语行为，一段话概括

Austin 注意到有些句子并不描述世界——它们改变世界。"我承诺。" "我请求。" "我宣布。" 他称这些为施事话语。Searle 将其形式化为五个类别：阐述类、指令类、承诺类、表达类、宣告类。KQML (Finin 等，1993) 将其软件代理化：消息是施事行为（动作）加内容（动作的内容）。FIPA-ACL 清理了 KQML 的空白，并围绕二十种施事行为进行了标准化。

### 二十种 FIPA 施事行为（部分列表）

| 施事行为 | 意图 |
|---|---|
| `inform` | "我告诉你 P 是真的" |
| `request` | "我请求你做 X" |
| `query-if` | "P 是真的吗？" |
| `query-ref` | "X 的值是什么？" |
| `propose` | "我提议我们做 X" |
| `accept-proposal` | "我接受这个提议" |
| `reject-proposal` | "我拒绝这个提议" |
| `agree` | "我同意做 X" |
| `refuse` | "我拒绝做 X" |
| `confirm` | "我确认 P 是真的" |
| `disconfirm` | "我否认 P" |
| `not-understood` | "你的消息无法解析" |
| `cfp` | "就 X 征集提案" |
| `subscribe` | "当 X 变化时通知我" |
| `cancel` | "取消正在进行的 X" |
| `failure` | "我尝试了 X 但失败了" |

完整列表见 `fipa00037.pdf` (FIPA ACL 消息结构)。重点不是死记硬背——重点是每一个都对应着 LLM 协议最终会重新添加的一个原语。

### 规范的 FIPA-ACL 消息

```
(inform
  :sender       agent1@platform
  :receiver     agent2@platform
  :content      "((price IBM 83))"
  :language     SL0
  :ontology     finance
  :protocol     fipa-request
  :conversation-id   conv-42
  :reply-with   msg-17
)
```

七个字段承载协议信封；一个字段 (`content`) 承载有效载荷。其余字段正是每次你在 JSON 协议上添加重试、线程和本体论时重新发明的那些。

### 两个遗留平台

**JADE** (Java 代理开发框架，1999-2020 年代) 是最常用的 FIPA 兼容运行时。代理扩展基类，交换 ACL 消息，在容器内运行，并使用"行为"进行协调。交互协议库随合同网、订阅-通知、请求-条件和提议-接受一起发布。

**JACK** (Agent Oriented Software，商业版) 在 FIPA 消息之上强调 BDI (信念-愿望-意图) 推理。更正式，采用较少。

一旦 Web 技术栈吞噬了多智能体用例，两者都衰落了。MCP 和 A2A 是 2026 年的运行时"容器"。

### FIPA 为何衰落

- **本体论开销。** FIPA 需要共享本体论来解析 `content`。就本体论达成一致是一个长达数年的标准化过程。Web 只是使用 HTTP + JSON。
- **没人使用的形式语义。** SL (语义语言) 提供了严格的真值条件，但大多数生产系统使用自由形式的内容并忽略形式主义。
- **工具锁定。** JADE 仅限 Java；JACK 是商业软件。多语言团队绕过两者。
- **互联网赢得了技术栈。** REST，然后是 JSON-RPC，然后是 gRPC 取代了 ACL 的传输层。

### LLM 复兴是轻量版 FIPA

比较 FIPA `request` 与 MCP `tools/call`：

```
(request                                {
  :sender  agent1                         "jsonrpc": "2.0",
  :receiver tool-server                   "method":  "tools/call",
  :content "(lookup stock IBM)"           "params":  {"name":"lookup_stock",
  :ontology finance                                   "arguments":{"symbol":"IBM"}},
  :conversation-id c42                    "id": 42
)                                        }
```

相同的信封，不同的语法。两者都携带：谁、对谁、意图、有效载荷、关联 ID。两者都不是对彼此的革命——它们是相同设计的不同权衡。

Liu 等人 2025 年的调查 ("Agent 互操作性协议综述：MCP、ACP、A2A、ANP"，arXiv:2505.02279) 明确指出了这一谱系：MCP 对应于工具使用言语行为，A2A 对应于智能体对等言语行为，ACP 对应于审计追踪言语行为，ANP 对应于去中心化身份扩展。新规范是具有 JSON 语法和更宽松语义的 ACL 后代。

### 权衡，直白地说

**FIPA 给你的而现代规范舍弃的：**

- 形式语义——你可以证明 `inform` 意味着发送者相信内容。
- 施事行为的标准目录——你不必重新争论"我们应该有 `cancel` 吗？"。
- 数十年的交互协议模式——合同网、订阅-通知、提议-接受——具有已知的正确性属性。

**现代规范给你的而 FIPA 没有的：**

- JSON 原生有效载荷，兼容每个现代工具。
- LLM 可以在没有手工编码本体论的情况下解释的自然语言内容。
- Web 技术栈传输 (HTTP、SSE、WebSocket)。
- 通过自描述文档进行能力发现 (MCP `listTools`，A2A Agent Card)。

更宽松的意图语义以换取更容易的实现。这就是确切的权衡。

### 值得移植的交互协议

FIPA 发布了约 15 种交互协议。有三种值得延续到 LLM 多智能体系统中：

1. **合同网协议 (CNP)。** 管理者发出 `cfp` (征集提案)；投标者以 `propose` 回应；管理者接受/拒绝。这是经典的任务市场模式 (第 16 阶段 · 第 16 课 协商)。
2. **订阅/通知。** 订阅者发送 `subscribe`；发布者在主题变化时发送 `inform`。这就是 2026 年的每个事件总线。
3. **请求-条件。** "当条件 Y 成立时执行 X。" 带前提条件的延迟操作。2026 年的类似物是持久工作流引擎中的延迟任务 (第 16 阶段 · 第 22 课 生产环境扩展)。

每一个都可以干净地映射到现代消息队列、HTTP + 轮询或 SSE 流。

### 当你舍弃本体论时会出什么错

没有共享本体论，智能体从自然语言内容中推断含义。有记录的 2026 年失败模式是**语义漂移**：两个智能体用同一个词 (`"customer"`) 指代略有不同的概念，接收方智能体基于错误的解释采取行动，没有模式验证器能捕获它。FIPA 的本体论要求会在解析时拒绝该消息。

没有完整本体论的缓解措施：

- `content` 上的 JSON Schema——在线拒绝结构性错误。
- 类型化制品 (A2A)——拒绝错误的模态。
- 信封中的显式施事行为——即使内容是自然语言也使意图明确。

### 2026 规范映射到言语行为传承

| 现代规范 | FIPA 类似物 | 保留的 | 舍弃的 |
|---|---|---|---|
| MCP `tools/call` | `request` | 显式意图、关联 ID | 形式语义、本体论 |
| MCP `resources/read` | `query-ref` | 显式意图、关联 ID | 形式语义 |
| A2A 任务生命周期 | 合同网 + 请求-条件 | 异步生命周期、状态转换 | 形式完整性保证 |
| A2A 流事件 | 订阅/通知 | 异步推送 | 类型化谓词订阅 |
| CA-MCP 共享上下文 | 黑板 (Hayes-Roth 1985) | 多写入者共享内存 | 逻辑一致性模型 |
| NLIP | 自然语言内容 | LLM 原生 | 模式 |

从上往下读这张表，模式是：保留结构原语，舍弃形式主义，让 LLM 掩盖歧义。

## 动手实践

`code/main.py` 实现了一个纯标准库的 FIPA-ACL 转换器。它对规范的 ACL 信封进行编码和解码，并展示每个 MCP/A2A 消息形状如何简化为相同的七个字段。演示包括：

- 将五个 MCP 风格和 A2A 风格的消息编码为 FIPA-ACL。
- 将 FIPA-ACL 解码回现代等效形式。
- 使用 `cfp`、`propose`、`accept-proposal`、`reject-proposal` 在管理者和三个投标者之间运行一个玩具合同网协商。

运行：

```
python3 code/main.py
```

输出是一个并排追踪，显示每条现代消息在其 2026 JSON 形式和其 FIPA-ACL 形式中的样子，然后是合同网投标的往返。相同的协议原语在往返中保留；只有语法不同。

## 使用它

`outputs/skill-fipa-mapper.md` 是一项技能，可以读取任何代理协议规范并生成 FIPA-ACL 映射。在采用新协议之前使用它来回答："这是真正的新东西，还是带有 JSON 语法的 `inform`？"

## 产出成果

不要把 FIPA-ACL 带回来。带回它的检查清单：

- 每条消息的意图原语（施事行为）是什么？
- 是否有用于请求-响应和取消的关联 ID？
- 是否有显式的内容语言（JSON-RPC、纯文本、结构化类型制品）？
- 交互协议是一等公民，还是你在从头重新实现合同网？
- 当两个智能体在内容含义上不一致时会发生什么（语义漂移）？

在生产环境发布任何新协议之前，为这五个问题编写文档。

## 关键术语

| 术语 | 人们怎么说 | 实际含义 |
|------|----------|----------|
| 言语行为 | "做某事的话语" | Austin/Searle：话语即行动。ACL 的理论之父。 |
| FIPA | "那个旧的 XML 东西" | IEEE 智能物理代理基金会。2000 年标准化了 ACL。 |
| ACL | "代理通信语言" | FIPA 的信封格式：施事行为 + 内容 + 元数据。 |
| 施事行为 | "动词" | 消息的意图类别：`inform`、`request`、`propose`、`cfp` 等。 |
| KQML | "FIPA 的前身" | 知识查询和操作语言 (1993)。更简单，更窄。 |
| 本体论 | "共享词汇" | 内容语言所谈论概念的形式化定义。 |
| SL0 / SL1 | "FIPA 内容语言" | 语义语言级别 0 和 1——形式化内容语言家族。 |
| 合同网 | "任务市场" | 管理者发出 cfp；投标者提议；管理者接受。经典的交互协议。 |
| 交互协议 | "消息模式" | 具有已知正确性的施事行为序列：请求-条件、订阅-通知等。 |
