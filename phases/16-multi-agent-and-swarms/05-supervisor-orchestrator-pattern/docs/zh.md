# 监督者/编排器-工作器模式

> 一个主导智能体规划和委托；专业工作器在并行上下文中执行并回报。这是 Anthropic 研究系统背后的模式（Claude Opus 4 作为主导，Sonnet 4 作为子智能体），在内部研究评估中比单智能体 Opus 4 提高 +90.2%。Anthropic 工程报告指出，80% 的 BrowseComp 差异仅由 token 使用量解释——多智能体获胜主要是因为每个子智能体获得全新的上下文窗口。本课程从原语构建监督者模式，并涵盖 2026 年生产部署的工程经验。

**类型:** 学习+构建
**语言:** Python (stdlib, `threading`)
**前置要求:** 阶段16课程04(Primitive Model)
**时间:** ~75分钟

## 问题背景

研究是单智能体系统失败的原型任务。你问"2023年到2026年间多智能体系统有什么变化？"单智能体按顺序读取五篇论文，用一半上下文填充它们的文本，然后必须同时对所有内容进行推理。到第五篇时它已经忘记了第一篇。它无法并行化。

监督者模式解决了这个问题：一个主导智能体规划搜索，将每个子问题委托给工作器，然后综合。每个工作器获得自己的 200k-token 窗口用于狭窄的问题。主导智能体从不看到原始论文——只看到工作器的摘要。

Anthropic 的生产研究系统报告称，相比单个 Opus 4，内部研究评估提高 +90.2%。同一篇文章指出，80% 的 BrowseComp 差异仅由 *token 使用量* 解释。每个子智能体的新鲜上下文是主要机制。

## 概念讲解

### 模式

```
                 ┌──────────────┐
                 │   Lead       │  规划、分解、
                 │  (Opus 4)    │  综合
                 └──┬────┬───┬──┘
                    │    │   │
            ┌───────┘    │   └───────┐
            ▼            ▼           ▼
      ┌─────────┐  ┌─────────┐  ┌─────────┐
      │ Worker1 │  │ Worker2 │  │ Worker3 │
      │(Sonnet) │  │(Sonnet) │  │(Sonnet) │
      └─────────┘  └─────────┘  └─────────┘
         新鲜       新鲜        新鲜
         上下文     上下文      上下文
```

主导智能体从不读取原始材料。工作器在主导智能体综合之前看不到彼此的工作。每个箭头是传递狭窄产物的交接。

### 为何获胜

三种机制：

1. **每个子智能体的新鲜上下文。**探索"FIPA-ACL遗产"的工作器不携带主导智能体规划时花费的 40k token。它获得一个 200k 窗口用于一个问题。
2. **通过提示词专业化。**主导智能体的提示词是"分解和综合"，而非"研究"。每个工作器的提示词是狭窄的："找出 X 有什么变化。"专注的提示词产生专注的输出。
3. **并行性。**工作器并发运行。实际时间大约是 `max(worker_times) + plan + synthesis`，而非 `sum(worker_times)`。

### 工程经验（Anthropic 2025）

Anthropic 的文章列出了几条至今仍相关的生产经验：

- **根据查询复杂度调整工作量。**简单查询：一个智能体，3-10 次工具调用。复杂查询：10+ 智能体。主导智能体必须估计这一点，而非调用者。
- **先宽后窄。**首先分解为广泛的子问题，然后如果答案需要深度，再为每个子问题生成更多工作器。
- **彩虹部署。**智能体是长期运行且有状态的。传统的蓝绿部署不起作用。Anthropic 使用彩虹：在新版本逐步推出时旧版本逐渐退出。
- **Token 使用量占主导。**多智能体是单智能体约 15× 的 token。只在任务价值值得成本时运行。

### LangGraph 的转向

LangGraph 最初发布了带有高级 `create_supervisor` 辅助函数的 `langgraph-supervisor` 库。2025 年 LangChain 将推荐转向直接通过工具调用实现监督者模式，因为工具调用对 *监督者看到什么*（上下文工程）提供更多控制。库仍然工作；文档现在推荐工具调用形式。

### 失败模式

- **主导智能体幻觉规划。**如果主导智能体生成的子问题没有分解真正的问题，工作器会对错误目标做精确研究。
- **工作器过度探索。**没有明确的范围边界，工作器会漂移到分配的子问题之外，污染综合步骤。
- **综合冲突。**两个工作器返回矛盾的事实。主导智能体必须重新询问（增加一轮）或明确记录分歧。静默选择一边是最糟糕的失败：用户永远不知道分歧发生了。

### 何时不该用监督者

- **顺序任务。**如果步骤 2 字面上需要步骤 1 的输出，并行化没有任何好处。使用流水线（CrewAI Sequential, LangGraph 线性图）。
- **简单查询。**单智能体更快更便宜地处理。在生成工作器之前使用主导智能体的"调整工作量"检查。
- **严格确定性。**监督者使用 LLM 选择的委托。当审计/重放比适应性更重要时，静态图更好。

## 动手实践

`code/main.py` 使用 `threading` 实现一个有三名并行工作器的监督者。主导智能体将查询分解为子问题，工作器并发运行每个子问题，主导智能体综合。没有真正的 LLM——工作器是脚本模拟的获取和摘要。

关键结构：

- `Lead.plan(query)` 将查询分成 3 个子问题。
- `Worker.run(sub_q)` 返回假摘要（在生产中可以是任何使用工具的智能体）。
- `Lead.run(query)` 在线程中启动工作器，等待它们，然后综合。

运行：

```
python3 code/main.py
```

输出显示规划、并行工作器追踪的开始/结束时间戳，以及最终综合。你可以看到实际时间的优势：三个 0.3 秒的工作器在约 0.35 秒内运行，而非 0.9 秒。

## 实际应用

`outputs/skill-supervisor-designer.md` 接受用户查询并产生监督者模式设计：主导系统提示词、工作器角色、子问题分解规则，以及综合模板。在构建新的研究型智能体系统之前使用它。

## 交付成果

部署监督者模式前的检查清单：

- **模型配对。**主导智能体使用推理级模型（Opus 类，`o3` 类）。工作器使用更快、更便宜的模型（Sonnet, `o4-mini`）。
- **工作器超时。**任何超过 2× 中位运行时间的工作器会被终止；主导智能体要么以更窄的范围重新生成，要么在没有它的情况下继续。
- **每个工作器的 token 上限。**硬限制（比如 10× 预期的综合输入）防止失控的工作器超出预算。
- **可观测性。**追踪主导智能体的规划、每个工作器的工具调用，以及综合。这是任何事后调试的基础。
- **彩虹推出。**有状态的长期运行智能体需要渐进式版本过渡，而非热切换。

## 练习题

1. 运行 `code/main.py`，然后修改主导智能体生成 5 个工作器而非 3 个。观察实际时间效果。在这个演示中，什么工作器数量会让生成开销超过并行节省？
2. 实现工作器超时：终止任何运行超过 0.5 秒的工作器，让主导智能体综合剩余结果。你需要什么可观测性来知道工作器被切断了？
3. 在主导智能体的综合中添加冲突检测步骤：如果两个工作器返回矛盾的答案，主导智能体记录分歧而非选择一个。如何在不调用 LLM 的情况下检测矛盾？
4. 阅读 Anthropic 研究系统工程文章。列出这个玩具演示需要采纳才能在生产中运行的三条实践。
5. 比较 LangGraph 的 `create_supervisor`（旧版）与新的工具调用推荐。哪个让你更好地控制监督者看到什么？为什么 Anthropic 在综合时只传递子答案而非原始工作器上下文？

## 关键术语

| 术语 | 人们怎么说 | 实际含义 |
|------|------------|----------|
| Supervisor | "主导智能体" | 规划、委托和综合的编排器智能体。不自己做工作。 |
| Worker | "子智能体" | 由监督者调用的专注智能体，具有狭窄范围和自己的上下文窗口。 |
| Orchestrator-worker | "监督者模式" | 同一事物的不同名称。2026 年文献使用两者。 |
| Fresh context | "干净窗口" | 工作器的上下文从系统提示词和分配的问题开始，而非主导智能体的历史。 |
| Rainbow deployment | "渐进推出" | 长期运行的有状态智能体需要版本化的退出和替换，而非蓝绿。 |
| Token dominance | "上下文是变量" | 80% 的研究评估差异来自使用的总 token，而非模型选择，根据 Anthropic。 |
| Scale effort | "根据复杂度匹配智能体数量" | 主导智能体估计查询难度，相应生成 1 或 10+ 工作器。 |
| Synthesis conflict | "工作器分歧" | 两个工作器返回矛盾的事实；主导智能体必须揭示分歧，而非静默选择。 |
